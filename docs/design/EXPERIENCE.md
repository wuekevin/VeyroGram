# EXPERIENCE — VeyroGram（v0.1 草案）

视觉令牌用 `{colors.*}`、`{rounded.*}` 等引用 DESIGN.md。冲突时 DESIGN.md 与本文件优先于任何截图或原型。

## Foundation
多端：Android（Kotlin）、iOS、Web、桌面（Electron，三栏）、管理后台、开发者平台、官网。手机优先的 IM 心智，桌面不是放大的手机页。深色优先、浅色同等验收；至少简体中文与英文；动态字体与 200% 放大不裁切。

## Information Architecture
**移动端底部 Tab（图标来自 `brand/icons/ui`，带文字标签）**：`chat` 会话 · `contacts` 联系人 · `moments` 动态 · `discover` 发现（小程序/扫一扫/表情商店入口）· `me` 我（资料、设备、隐私、收藏、设置、订阅）。
**桌面/Web 三栏**：左侧窄栏（会话/联系人/动态/发现/设置）→ 列表栏 → 会话与详情栏；快捷键与拖拽文件为一等公民。
**管理后台侧栏**：概览 `dashboard` · 用户与设备 `users-admin`/`device` · 群与消息 `group`/`chat` · 举报与审核 `flag` · 客服与工单 `support`/`ticket` · 媒体 `image` · 运营 `megaphone` · 订阅 `wallet` · 开发者与小程序审核 `miniapp`/`bot` · 报表 `chart` · 审计 `audit` · 系统配置 `settings` · 权限 `key`。
**开发者平台**：应用清单 → 应用配置 → 密钥 `key`（只展示一次）→ 授权设置 → 版本与审核 → 统计 → 团队。
**官网**：首页 / 功能 / 安全与隐私 / 下载 / 版本公告 / FAQ / 开发者 / 状态 / 法务。

闭环检查：PRD 的 FR-1…FR-72 每个用户可见能力都映射到上述一个界面入口，映射表在 DESIGN-SYSTEM.md §6；尚无入口的项（FR-58/59/60）属本期不排期。

## Voice and Tone
清晰、克制、不夸张。错误文案说明“发生了什么 + 能做什么”，不责怪用户。**禁止未经验证的承诺**：不写“绝对安全/端到端加密/无限群/秒达”。隐私相关文案用具体事实（“仅你可见”“对方不会收到通知”）。中英文同级维护，文案走 i18n 资源，不硬编码。

## Component Patterns
- **会话列表项**：头像 + 名称 + 末条预览 + 时间 + 未读徽标；免打扰显示 `bell-off`；置顶 `pin`；长按/右键菜单（置顶、免打扰、删除）。
- **消息气泡**：发出方右、接收方左；状态（发送中/失败可重试/已送达/已读，已读受隐私设置约束）；长按菜单：`reply` 回复、`forward` 转发、`star` 收藏、`edit` 编辑、撤回、`trash` 删除、`heart` 点赞、`flag` 举报。
- **输入栏**：文本、`mic` 语音、`image`/`video`/`file`/`location` 附件、`sticker` 表情、`send` 发送；输入中状态对方可见（可在隐私里关闭）。
- **权限弹窗**：先解释用途再触发系统授权；拒绝后给出设置入口，不循环弹出。
- **危险操作**：删除/注销/撤销设备需二次确认，说明后果；高危后台操作显示审批状态。

## State Patterns
每个页面具备：**加载**（骨架屏）、**空**（说明 + 下一步动作）、**错误**（原因 + 重试）、**离线**（顶部条 + 队列中的发送）、**无权限**（说明谁可以操作）、**降级**（旧版本不支持的消息类型显示“当前版本不支持该消息”）。管理后台每页必须有真实数据动作与这三类状态（BMAD-MASTER §7）。

## Interaction Primitives
轻触、长按（菜单）、滑动（会话列表快捷操作）、拖拽排序（朋友圈 9 图、表情包、标签）、桌面右键/快捷键（`Cmd/Ctrl+K` 搜索、`Esc` 返回/关闭）、文件拖放上传。动效 120/200/320ms，`prefers-reduced-motion` 时改为淡入淡出。

## Accessibility Floor
对比度见 DESIGN.md（44 项检查全部通过，由脚本实际计算）；全部图标有无障碍名称（`icons.json` 的中英文标签）；可聚焦元素有可见焦点环（≥3:1）；触控目标 ≥ 48dp/44pt；VoiceOver/TalkBack 能读出消息发送者、时间、状态；状态不仅靠颜色表达；字体 200% 放大布局不破；键盘可完成全部桌面操作。目标 WCAG 2.1 AA，**未经审计前不宣称已合规**。

## Responsive & Platform
- **手机（360/390）**：单栏，底部 Tab，系统返回手势优先；Android 遵循 Material 手势与状态栏，iOS 遵循 HIG 与 Dynamic Type。
- **平板（≥600）**：双栏（列表 + 会话）。
- **桌面（≥960）**：三栏；窗口拖拽、托盘/菜单栏图标（简化符号）、系统通知、文件拖拽、离线恢复与更新提示。
- **管理后台**：桌面优先（≥1280），最小支持 1024；表格支持列配置与导出（受审批）。
- **官网**：移动优先响应式，SEO、性能预算与国际化。
- **小程序容器**：顶部固定宿主栏（返回/关闭/分享），授权弹窗由宿主绘制，不可被小程序伪造。

## Key Flows
映射 PRD 的旅程（UJ-1…UJ-7）：换机恢复（设备批准 → 同步）、群主清理广告（长按撤回 → 禁言 → 举报）、桌面发起会议（呼叫/忙线/重连）、朋友圈部分可见（标签选人）、开发者上线小程序（扫描 → 审核 → 灰度 → 回滚）、客服接待与 SLA、运营验证端口隔离与恢复演练。每个流程的高保真原型是 Phase 3 编码前的**审批门禁**（见 DESIGN-SYSTEM.md §5）。已产出 22 个原型页、94 张截图基线（见 `prototypes/`、`baselines/`），覆盖登录、设备批准/管理、扫码登录、会话与聊天、消息编辑与已读详情、群管理、朋友圈发布、通话、设置、小程序授权与市场、客服工作台、后台与开发者控制台、官网、平板双栏及状态集；签字待定（见 APPROVALS.md）。

## Inspiration & Anti-patterns
借鉴：IM 的成熟交互心智（列表/气泡/长按菜单）。避免：上游页面样式复用、手机页放大到桌面、把 Emoji 当图标、渐变铺满、红点轰炸、暗黑模式只反色。

# WCAG 2.1 AA 验收清单（50 条成功标准）

> **这不是合规声明。** WCAG 合规是对**已实现的产品**做完整测试（含辅助技术与真机）后才能下的结论。本清单用于：① 记录设计/原型阶段已有的证据；② 作为各端发布前的**必过验收门禁**；③ 明确哪些条目必须人工测试。
> 证据来源：`packages/design-tokens/check_contrast.py`（令牌对比度）、`tools/a11y_scan.py`（axe-core + 键盘焦点 + 目标尺寸 + 裁切 + 回流，96 次运行含 200% 字号、320px、英文、明暗）、`docs/design/a11y-axe-report.json`。

状态说明：
- **PASS-PROTO**：已在原型上由脚本/检查验证（产品实现后仍须在各端重做）
- **DESIGN-RULE**：已写入令牌/规范，实现后必须验证
- **MANUAL**：必须人工/辅助技术测试，见 ACCESSIBILITY-REVIEW-GUIDE.md
- **IMPL**：只能在已实现产品上测试
- **N/A**：不适用（附理由）

汇总：A 级 30 条 + AA 级 20 条 = 50 条；DESIGN-RULE 11，IMPL 10，MANUAL 6，N/A 2，PASS-PROTO 21。

## 发布门禁（写入 DoD）
1. 每个客户端（Android / iOS / Web / 桌面 / 后台 / 开发者平台 / 官网）发布前须复制本表，逐条填写**该端**的结果与证据；任何 A/AA 条目为“未通过”则不得宣称 WCAG 2.1 AA 合规。
2. MANUAL 与 IMPL 条目必须有测试记录（见 `a11y-manual-test-log.md` 模板），含测试人、设备/辅助技术、结果。
3. 建议在首个公开发布前委托第三方做无障碍审计，并出具 ACR/VPAT。
4. 本表“PASS-PROTO”条目不能替代实现后的复测。

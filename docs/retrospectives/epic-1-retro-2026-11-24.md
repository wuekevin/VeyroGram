## 发现（每条带来源）

### F1 已修：Story 文件状态与 sprint-status 不一致
- 来源：`docs/stories/1.3/1.4/1.5/1.6-*.md` 的 frontmatter 为 `backlog`，而 `sprint-status.yaml` 记 `review`，且这四个文件都有 Dev Agent Record；1.14/1.17/1.18/1.20 文件为 `backlog`，tracker 为 `ready-for-dev`；`epic-1` 记 `backlog` 但已有 19 个 Story 在 review。
- 处理：已把八个 Story 文件状态改成与 tracker 一致，`epic-1` 改为 `in-progress`；用 `tools/gen_epics.py` 重生成验证状态能保留（该生成器会保留 status 和 Dev Agent Record，见 `tools/gen_epics.py:172`）。
- 副作用：重生成会覆盖 Story 1.9 手写的核验说明，已用 `git checkout` 还原。

### F2 未解：生成器会覆盖手写内容（1.9）
- 来源：`tools/gen_epics.py:172-182` 只保留 status 和 `## Dev Agent Record` 之后的内容；1.9 的手写说明不在其内。
- 建议：把 1.9 的说明挪进它的 Dev Agent Record 段，或让生成器报告被覆盖的差异。

### F3 未解：没有一个 Story 到 done，19 个停在 review
- 来源：`sprint-status.yaml` 第 39–62 行。review 之后的 code-review 与验收没有发生；这批代码目前只有自己写、自己测。
- 影响：回顾判据"不得有未完成 Story"，机器结论为 rejected（见下）。

### F4 未解：客户端侧没有端到端闭环
- 来源：1.14、1.17、1.18、1.20 未开工；1.11 AC3 缺 API 客户端拒绝无效证书的测试、真机签名下 Keychain、视频播放（`docs/stories/1.11-*.md`）。
- 影响：账号、聊天后端和三端 IM SDK 互通（`docs/architecture/im-sdk-compat.md`）有证据，但"用户在客户端登录并发出第一条消息"这条纵切没有被任何一个客户端实现验证。这些 Story 依赖设计门禁 G1–G6，而它们由用户签字（`docs/design/APPROVALS.md`）。

### F5 未解：互通测试不在 CI
- 来源：`tools/ci_local.sh` 第 11 行 NOTE；Web 互通依赖 `tests/imsdk/web/node_modules`，Android 要 adb 设备，iOS 要模拟器。缺条件时自动跳过，因此 CI 绿不能说明三端 SDK 与固定版 WuKongIM 兼容。
- 建议：Web 互通先接入 Linux CI（只需 Node 和已构建的 WuKongIM 二进制）；Android/iOS 需要模拟器 runner，成本高，单独决定。

### F6 未解：WuKongIM 版本和品牌残留
- 来源：构建出的二进制报告 `version=dev`；beta.30 在 `internal/access/api` 之外的改动未重新审计（提交 `472e971`）；登录页仍是上游品牌（Story 9.7 已排期处理）。

### F7 已知限制，非缺陷
- Android SDK 遇错误令牌无限退避重连而不报认证失败，iOS 则明确报 AUTHFAIL；客户端令牌失效必须由 HTTP 401 驱动（`docs/architecture/im-sdk-compat.md`）。
- 互通测试未覆盖断线重连成功、离线消息、群聊、TLS、真机、旧系统版本。

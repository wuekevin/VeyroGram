# Story 1.13: 设备、令牌与会话撤销（服务端）

**Epic 1：账号与最小聊天纵切（可信基座）（本 Story：Phase 2）** · 规模 M（S=半天–1天，M=1–3天，L=3–7天；按单个开发 Agent 的上下文可完成估算）

As a 终端用户,
I want 登录后每台设备有独立记录，并能撤销任一设备,
So that 丢失设备或账号被盗时能立即止损.

## 验收标准（Acceptance Criteria）
**Given** 用户在两台设备登录
**When** 撤销其中一台
**Then** 该设备访问令牌在 60 秒内失效并通过 /user/device_quit 关闭其 IM 会话

**Given** 刷新令牌被重放
**When** 检测到复用
**Then** 整条令牌链吊销并通知其他设备

**Given** 同设备类别的两台设备
**When** 撤销一台
**Then** IM 令牌轮换，另一台通过刷新令牌自动重取，不出现永久掉线

**Given** 访问令牌
**When** 设备被撤销
**Then** Redis 拒绝列表覆盖全部已认证路由（每请求一次查询），Redis 不可用时降级为令牌 TTL（≤15 分钟）并告警

**Given** 多节点 IM 集群
**When** 调用 /user/device_quit
**Then** 仅保证 owner-local 会话关闭；v1 按单节点交付，集群上线前必须通过踢线传播测试

**Given** 用户退出登录
**When** 确认
**Then** 撤销该设备令牌与 IM 令牌并清除本地凭据

## 测试（含安全负面测试）
- 安全负面：被吊销令牌访问 API 与 IM 均失败
- 集成：单节点 IM 的踢线与令牌轮换
- 时延：撤销生效时间测量（≤60 s 目标）
- 降级：Redis 故障时撤销生效时间退化为 TTL，告警触发

## Dev Agent Record
- 状态：review（服务端部分）。新增 `platform/denylist`（Redis 拒绝列表，条目 TTL = 访问令牌 TTL + 1 分钟，自动过期）、`platform/authn`（逐请求校验访问令牌并查一次拒绝列表）、迁移 `0004_im_epoch`、接口 `GET /v1/devices`、`DELETE /v1/devices/{id}`、`POST /v1/auth/logout`、`GET /v1/im/token`（契约已写入 `auth.yaml`）、worker 处理 `identity.im_sync`。
- 机制：撤销 = 在同一事务内标记设备、作废其刷新令牌、给该设备类别的 IM epoch 加一并写 outbox（`identity.im_sync`）；随后写 Redis 拒绝列表（访问令牌立即失效）；worker 随后对 WuKongIM 先 `device_quit`（清旧令牌并踢线）再 `user/token` 注册新令牌。IM 令牌由 `HMAC(IM 密钥, uid|类别|epoch)` 推导，库里不存任何令牌明文；同类别另一台设备被踢后，用自己的访问令牌再调 `/v1/im/token` 即可取到新令牌，不会永久掉线。刷新令牌复用检测除原有吊销外，现在同样写拒绝列表并轮换 IM 令牌。已吊销的设备 id 永不复活：同一台物理设备重新登录会得到新的设备 id，旧访问令牌继续失效。非本人或不存在的设备一律 404。
- 降级：Redis 不可达时请求放行（吊销退化为访问令牌 TTL ≤ 15 分钟）并计入 `vg_auth_denylist_degraded_total`，告警 `VeyroGramDenylistDegraded`（promtool 单测通过）；但 `/v1/im/token` 和刷新走数据库判断，被吊销的设备即使 Redis 挂了也拿不到 IM 令牌。无效/过期令牌无论 Redis 状态都不放行。
- 测试（真实 MySQL 8.0 + 真实 Redis 7.4.2 + 真实补丁 WuKongIM）：撤销两台设备之一后被撤销设备访问令牌立即 401（本机实测约 4 ms，目标 ≤ 60 s）、刷新令牌失效、另一台不受影响、重复撤销幂等、列表消失；越权撤销他人设备 404；无令牌 401；退出登录；同类别撤销后 IM 令牌轮换且 worker 先踢后注册、两端推导一致、另一台能重取；Redis 故障降级与告警计数；复用检测立即杀访问令牌并排队 IM 轮换；重新登录得新设备 id；IM 故障返回干净 503；真实二进制 + 真实 WuKongIM：令牌注册成功，登出后 worker 对真实 IM 完成同步（outbox 状态 done，epoch 加一）。
- 未完成（诚实说明）：① “通知其他设备”（复用检测/新设备登录提醒）没有做：需要通知/推送通道（后续 Story），目前只有 `login_event` 记录和指标；② 多节点 IM 集群的踢线传播未做也未测，v1 仅单节点（AD-9 已明示 owner-local 限制）；③ 用真实 WebSocket 客户端验证“被踢后用新令牌重连成功”未做——只验证了 IM 接受令牌注册与踢线调用，没有建立真实 IM 连接；④ 60 秒时延目标只在本机单进程测量，生产需在真实网络下复测；⑤ Redis 密码/ACL、Redis 持久化策略属于运维（见清单 C）；⑥ 拒绝列表按设备粒度，尚无“账号级全部登出”接口。

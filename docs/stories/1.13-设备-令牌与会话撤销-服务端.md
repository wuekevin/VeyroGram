# Story 1.13: 设备、令牌与会话撤销（服务端）

**Epic 1：账号与最小聊天纵切（可信基座）（本 Story：Phase 2）** · 规模 M（S=半天–1天，M=1–3天，L=3–7天；按单个开发 Agent 的上下文可完成估算）

As a 终端用户,
I want 登录后每台设备有独立记录，并能撤销任一设备,
So that 丢失设备或账号被盗时能立即止损.

## 验收标准（Acceptance Criteria）
**Given** 用户在两台设备登录
**When** 撤销其中一台
**Then** 该设备访问令牌在 60 秒内失效并通过 /user/device_quit 关闭其 IM 会话

**Given** 刷新令牌被重放
**When** 检测到复用
**Then** 整条令牌链吊销并通知其他设备

**Given** 同设备类别的两台设备
**When** 撤销一台
**Then** IM 令牌轮换，另一台通过刷新令牌自动重取，不出现永久掉线

**Given** 访问令牌
**When** 设备被撤销
**Then** Redis 拒绝列表覆盖全部已认证路由（每请求一次查询），Redis 不可用时降级为令牌 TTL（≤15 分钟）并告警

**Given** 多节点 IM 集群
**When** 调用 /user/device_quit
**Then** 仅保证 owner-local 会话关闭；v1 按单节点交付，集群上线前必须通过踢线传播测试

**Given** 用户退出登录
**When** 确认
**Then** 撤销该设备令牌与 IM 令牌并清除本地凭据

## 测试（含安全负面测试）
- 安全负面：被吊销令牌访问 API 与 IM 均失败
- 集成：单节点 IM 的踢线与令牌轮换
- 时延：撤销生效时间测量（≤60 s 目标）
- 降级：Redis 故障时撤销生效时间退化为 TTL，告警触发

## 配置与回滚
- **配置/决策点：** 访问令牌 TTL ≤15 分钟；Redis 拒绝列表
- **回滚方案：** 关闭拒绝列表仅退化为 TTL 过期；令牌密钥通过 kid 轮换

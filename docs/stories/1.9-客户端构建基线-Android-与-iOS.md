# Story 1.9: 客户端构建基线：Android 与 iOS

**Epic 1：账号与最小聊天纵切（可信基座）（本 Story：Phase 2）** · 规模 M（S=半天–1天，M=1–3天，L=3–7天；按单个开发 Agent 的上下文可完成估算）

As a 客户端开发者,
I want 四端客户端在隔离环境可复现构建，依赖与包名问题清零,
So that 后续各端界面与功能 Story 有可编译、可测试的起点（R-12/13/15/17/19）.

## 验收标准（Acceptance Criteria）
**Given** Android
**When** 构建
**Then** 使用 VeyroGram 包名而非 com.test.ts，应用 ID 与 R 导入重构完成，debug APK 可复现构建

**Given** iOS
**When** 构建
**Then** 过期 Pods（含 AFNetworking）已替换或升级，在 Xcode 26 工具链下无签名模拟器构建通过

**Given** Android 与 iOS
**When** 在隔离环境运行
**Then** 无签名 debug 构建与单元测试可由脚本一键复现，并保存日志

## 测试（含安全负面测试）
- 可复现构建：四端在干净环境各构建一次并保存日志
- SCA：npm/Gradle/Pods 高危为零

## 验证补充（第二轮）
- Android 在 API 37 arm64 模拟器里实机启动：首次启动曾**崩溃**（上游在未配置 `api_base_url` 时抛 `IllegalStateException`，去掉厂商默认地址后必现），已改为用 `BuildConfig.VG_API_BASE_URL`（默认 `http://127.0.0.1:8080`，`-PvgApiBaseUrl=` 覆盖）。修复后启动到隐私弹窗，同意后进入登录页（显示 VeyroGram）；无崩溃。APK sha256 更新为 c2f4508c…，两次干净构建一致。
- iOS：发现并移除 Tencent Bugly（用厂商应用 ID 上报用户 ID）；YYImage 自带 WebP.framework 改用 libwebp。iOS 同一路径下两次干净构建，主可执行文件 sha256 一致（b49d164c…；换路径不保证一致，Mach-O 带路径）。iOS 应用仍**未能在模拟器启动**（AMR 预编译库只有真机 arm64 切片，见 apps/ios/README.md）。
- CI 的 `supply-chain` 作业曾因补丁里带出被删除的厂商凭据旧值而失败；已把这些改动移出补丁（overlay + 脚本删除）。注意：首个提交 1c0023e 的历史里仍含这些上游**公开示例**凭据（来自上游公开仓库），私有仓库，未改写历史。

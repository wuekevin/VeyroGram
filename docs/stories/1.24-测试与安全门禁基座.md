# Story 1.24: 测试与安全门禁基座

**Epic 1：账号与最小聊天纵切（可信基座）（本 Story：Phase 2）** · 规模 M（S=半天–1天，M=1–3天，L=3–7天；按单个开发 Agent 的上下文可完成估算）

As a 工程团队,
I want 自动化的契约、越权、重放与供应链门禁,
So that 防止回归和默认值/依赖风险再次进入主干.

## 验收标准（Acceptance Criteria）
**Given** 提交 PR
**When** CI 运行
**Then** 产出 SBOM、SCA、许可证扫描、secret 扫描并对高危阻断（含 UNLICENSED/Custom 商业许可）

**Given** 新增路由
**When** 运行生成式越权测试
**Then** 非属主、已移除成员、已拉黑、跨租户、过期令牌全部被拒

**Given** 修改 OpenAPI
**When** 运行 diff 门禁
**Then** 破坏性变更需升版本或 ADR

## 测试（含安全负面测试）
- 安全负面：重放、过期令牌、跨租户样例
- 合约：OpenAPI 与消息类型 schema
- 回归：上游测试不可作基线，自建核心 E2E 套件

- **门禁发现的真实问题（已修）：**

  2. **Go 标准库漏洞 GO-2026-6859**（`net/http` 在 go1.26.10：HTTP/1 服务器可被 MaxBytesReader 头部竞争崩溃），我们的代码可达。修复：工具链升到 **go1.26.11**，并重新编译打补丁的 WuKongIM（`tools/build_wukongim.sh` 现在默认 1.26.11，可用 `WK_GOTOOLCHAIN` 覆盖），全量集成测试在新工具链下通过。

# Story 9.3: 内容审核队列

**Epic 9：管理后台商业运营能力（本 Story：Phase 3）** · 规模 M（S=半天–1天，M=1–3天，L=3–7天；按单个开发 Agent 的上下文可完成估算）

As a 内容审核员,
I want 统一的待审队列处理举报内容、头像、动态、表情,
So that 高效一致的审核.

## 验收标准（Acceptance Criteria）
**Given** 待审内容
**When** 审核
**Then** 通过、下架或升级，结果写审计并通知

**Given** 多审核员
**When** 并发
**Then** 单条内容不被重复处理

**Given** 申诉
**When** 复核
**Then** 与首审不同人

**Given** 用户头像与群头像
**When** 命中规则或被举报
**Then** 进入审核队列，违规被替换并通知

## 测试（含安全负面测试）
- 安全负面：越权审核；并发处理
- E2E：审核流
- 指标：处理时长

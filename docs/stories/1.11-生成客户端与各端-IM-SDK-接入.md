# Story 1.11: 生成客户端与各端 IM SDK 接入

**Epic 1：账号与最小聊天纵切（可信基座）（本 Story：Phase 2）** · 规模 M（S=半天–1天，M=1–3天，L=3–7天；按单个开发 Agent 的上下文可完成估算）

As a 客户端开发者,
I want 由 OpenAPI 生成的各端客户端与固定版本的 IM SDK 接入层,
So that 各端不各自实现协议与状态规则（AD-17）.

## 验收标准（Acceptance Criteria）
**Given** OpenAPI 契约
**When** 生成
**Then** 产出 TS/Kotlin/Swift/Go 客户端并随版本发布

**Given** IM SDK
**When** 接入
**Then** 固定到与服务端 WuKongIM 兼容的版本，并有对该固定版本的契约测试

**Given** 令牌
**When** 保存
**Then** 使用系统安全存储，校验服务器证书，敏感数据排除系统备份

## 测试（含安全负面测试）
- 合约：生成客户端对契约样例通过
- 安全负面：证书校验失败拒绝连接；备份排除验证
- 兼容：IM SDK 与 WuKongIM 固定 SHA 互通

## Dev Agent Record
- 状态：**部分完成（in-progress）**。AC1 的生成部分已做并验证；AC2、AC3 依赖客户端工程（Story 1.9/1.10），Mac 上现在做不了，原样保留。
- AC1（生成客户端）：`tools/gen_clients.py` 从 `packages/contracts/openapi/*.yaml` 生成 TypeScript、Go、Kotlin、Swift 四个客户端（28 个操作、42 个类型）到 `packages/clients/`。没有用 openapi-generator，而是仓库内的小生成器：契约只用 OpenAPI 的一个小子集，生成器遇到不支持的写法（oneOf/allOf/匿名对象/未声明的路径参数）直接报错而不是猜；不下载、不执行第三方代码（AD-18）。CI 用 `--check` 保证“改契约必须重新生成客户端”。
- 验证：Go 客户端被 `services/api/cmd/api/clientcontract_test.go` **对着真实 API 端到端驱动**（短信码→登录→设备→IM 令牌→拉黑/取消→带开放 payload 的发消息→错误信封→刷新轮换与旧令牌被拒→登出后令牌被拒）；TypeScript 过 `tsc --strict`；Swift 过 `swiftc -typecheck`（Mac 上）。**Kotlin 客户端只生成、没编译过**（本机没有 Kotlin 工具链），到 Story 1.9 的 Android 工程里才会第一次编译。
- 写生成器时发现并修了：开放对象（消息 payload 允许 `type` 之外的字段）一开始被生成成只有 `type` 的结构，会悄悄丢掉 `content`；现在 Go 保留 `Extra`、TypeScript 用索引签名、Kotlin/Swift 用通用 JSON 对象。`Error` 模式名会遮蔽语言内置的 Error，改名为 `ErrorBody`。
- 未做：**发布**（“随版本发布”）到 npm/Maven/SwiftPM 需要注册表账号，见清单；**AC2** 的 IM SDK 固定版本与互通契约测试（要 Android/iOS/Web 工程）；**AC3** 的系统安全存储、证书校验失败拒绝连接、备份排除（要真机/模拟器）。生成的客户端只提供 token 提供者接口，不保存令牌。

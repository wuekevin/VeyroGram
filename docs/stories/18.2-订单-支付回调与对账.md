# Story 18.2: 订单、支付回调与对账

**Epic 18：订阅、权益与支付（本 Story：Phase 6）** · 规模 L（S=半天–1天，M=1–3天，L=3–7天；按单个开发 Agent 的上下文可完成估算）

As a 终端用户,
I want 创建订单并支付，回调验签幂等，日终对账,
So that 可靠、可核对的交易.

## 验收标准（Acceptance Criteria）
**Given** 支付回调
**When** 验签失败或重复
**Then** 拒绝且重放不重复入账

**Given** 日终对账
**When** 运行
**Then** 差异可见并有处理流程

**Given** 退款
**When** 发起
**Then** 状态机与审计完整

**Given** 订单金额与币种
**When** 客户端或回调篡改
**Then** 以服务端订单为准，金额/币种不一致拒绝，退款不得超过实付

**Given** 移动端数字内容订阅
**When** 上架
**Then** 通过商店内购（Apple IAP / Google Play Billing）并做服务端回执校验；或在 v1 明确不在移动端售卖并仅提供 Web 支付，由 OQ-3/OQ-5 决策

## 测试（含安全负面测试）
- 安全负面：回调重放与伪造
- 集成：沙箱支付
- 对账：差异场景演练
- 安全负面：金额/币种篡改、超额退款、回调乱序

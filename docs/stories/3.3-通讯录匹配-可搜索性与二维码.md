# Story 3.3: 通讯录匹配、可搜索性与二维码

**Epic 3：联系人与社交关系（本 Story：Phase 3）** · 规模 M（S=半天–1天，M=1–3天，L=3–7天；按单个开发 Agent 的上下文可完成估算）

As a 终端用户,
I want 授权后用通讯录找到朋友，控制能否被手机号/短号搜到，扫码加好友或入群,
So that 更快找到人且隐私可控.

## 验收标准（Acceptance Criteria）
**Given** 用户授权通讯录
**When** 匹配
**Then** 使用带服务端密钥的 HMAC（非裸哈希）与限频接口，原始通讯录不落盘明文，防止对手机号空间的暴力还原

**Given** 关闭“手机号可被搜索”
**When** 他人按手机号搜索
**Then** 无结果且不泄露存在性

**Given** 二维码
**When** 过期或被撤销
**Then** 失效；群二维码入群的邀请确认由 4.4 实现

**Given** 用户拒绝通讯录权限
**When** 再次进入
**Then** 功能降级并给出设置引导，不循环弹窗

**Given** 扫描个人名片二维码
**When** 识别
**Then** 需用户确认后才发起添加

## 测试（含安全负面测试）
- 安全负面：枚举攻击与限频；二维码重放
- E2E：授权与拒绝权限
- 无障碍：扫码页读屏
- 安全负面：手机号空间枚举/彩虹表还原尝试被限频与密钥化阻断

## 配置与回滚
- **配置/决策点：** 匹配批量上限；二维码有效期
- **回滚方案：** 关闭匹配开关则入口隐藏

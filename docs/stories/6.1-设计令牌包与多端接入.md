# Story 6.1: 设计令牌包与多端接入

**Epic 6：统一品牌与设计系统落地（本 Story：Phase 3）** · 规模 M（S=半天–1天，M=1–3天，L=3–7天；按单个开发 Agent 的上下文可完成估算）

As a 客户端开发者,
I want 一个由 tokens.json 生成的多端令牌包,
So that 各端颜色/字号/间距一致，不再各自为政.

## 验收标准（Acceptance Criteria）
**Given** 修改 tokens.json
**When** 构建
**Then** 生成 CSS、Android colors（含 night）、iOS Swift，且对比度脚本不通过则构建失败

**Given** 客户端使用令牌
**When** 评审
**Then** 不允许出现未登记的硬编码颜色（lint）

**Given** 渐变背景上的正文
**When** 使用
**Then** 只能使用 gradient.action

**Given** 任何端的界面
**When** 评审
**Then** 不得保留上游页面样式或仅替换 Logo/主题色，需对照设计规范

## 测试（含安全负面测试）
- 单元：check_contrast.py 反向用例
- 视觉回归：令牌变更触发基线对比
- 合约：令牌版本号

## 跨端任务
| 列 | 任务 |
|---|---|
| Server | 不适用：不涉及服务端变更 |
| Android | 接入 colors.xml/Compose 主题 |
| iOS | 接入 VGTokens.swift |
| Web | 接入 tokens.css |
| Desktop | 接入 tokens.css |
| Manager | 接入 tokens.css |
| API | 不适用：不新增/变更接口 |
| DB | 不适用：不涉及数据库变更 |
| 通知 | 不适用：不触发通知 |
| 权限 | 不适用：无新增权限规则（沿用既有策略） |
| E2E | 令牌回归 |

## 配置与回滚
- **配置/决策点：** 令牌版本语义化
- **回滚方案：** 令牌只增不删，废弃项保留一个版本

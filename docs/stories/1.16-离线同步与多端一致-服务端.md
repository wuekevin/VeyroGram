# Story 1.16: 离线同步与多端一致（服务端）

**Epic 1：账号与最小聊天纵切（可信基座）（本 Story：Phase 2）** · 规模 M（S=半天–1天，M=1–3天，L=3–7天；按单个开发 Agent 的上下文可完成估算）

As a 终端用户,
I want 换设备或离线后重新上线，消息、未读数与草稿自动补齐,
So that 跨设备体验一致，不丢消息.

## 验收标准（Acceptance Criteria）
**Given** 新设备首次登录
**When** 同步
**Then** 按游标分页补齐会话与消息，未读数与旧设备一致

**Given** 用户在 A 设备编辑草稿
**When** 5 秒后
**Then** B 设备显示同一草稿 [假设值待测]

**Given** 离线 10 分钟
**When** 重连
**Then** 离线期间消息按序补齐无重复

## 测试（含安全负面测试）
- E2E：断网重连、换机恢复
- 性能：同步分页的 P95 延迟记录
- 安全负面：同步接口不返回已不属于该用户的会话

## Dev Agent Record
- 状态：review（服务端部分；各端同步 UI 与本地库属于客户端 Story）。新增 `internal/conversation` 模块（domain/ports/app/adapters/http）、迁移 `0006_conversation_state`（`sync_clock`、`draft`、`conversation_setting`）、接口 `GET /v1/sync/conversations`、`GET /v1/sync/messages`、`POST /v1/sync/read`、`PUT /v1/sync/drafts`、`PUT /v1/sync/conversation-settings`、`GET /v1/sync/state`（契约 `packages/contracts/openapi/sync.yaml`），imgw 新增 `ConversationSync`/`ChannelMessageSync`/`ClearUnread`。
- 设计：消息与未读以 IM 为准（客户端不能直连 IM 的 HTTP API，所以由我们包一层）；用户永远取自访问令牌，接口里没有 uid 参数。会话列表游标不透明且带版本（`c1.`），未知版本返回 400 让客户端从头来；消息按 `after_seq`（不含）向前翻页，多取一行判断 `has_more`，并在我们这一层排序、去重、丢弃小于等于游标的行。草稿与会话设置用每用户独立的 `sync_clock` 发号（行锁串行，版本唯一且无缺口），`GET /v1/sync/state?since=` 只返回之后的变化；清空草稿保留为墓碑（`deleted`）让其他设备知道。变化通过 outbox `conversation.state_changed` 由 worker 以 `vg_system` 向该用户其他设备发 `sync_notice`（只含 kind/peer/version，不含草稿文字）。表按 uid 存，不外键到身份模块的表（AD-1）。
- 验证（真实 MySQL + 真实补丁 WuKongIM + 真实 WebSocket，`TestSyncCatchUpUnreadDraftsAndIsolationOverRealIM`）：A 给离线的 B 发 7 条；B 的全新设备拉会话列表得到唯一会话、unread=7、最新 2 条按旧到新排列；按每页 3 条翻页得到 1..7 各一次且顺序正确（3 页）；B 的另一台设备看到同样的 unread=7；一台设备标记已读后所有设备 unread=0；B 断线期间 A 再发 5 条，重连后从 after_seq=7 恰好拿到 8..12 且无重复，unread=5；B1 写草稿 → B2 在 5 秒内收到 `sync_notice` 且通知里没有草稿文字 → B2 拉到同样的草稿；清空后以墓碑同步；`since` 只返回之后的变化且按版本排序；20 个并发写得到 20 个不同版本；隔离：无关用户看不到任何会话/消息/状态，传复合会话 id、`vg_system`、坏游标、负数 seq 均 400，未登录 401，`vg_system` 会话不出现在列表；应用层单测覆盖排序/去重/has_more/限制钳制/游标校验/IM 故障分类。
- 本机测量（不是通过门槛）：12 条消息、单机：会话页 p50≈0.7 ms、p95≈2.9 ms；消息页 p50≈0.7 ms、p95≈5.3 ms。数据量和并发都很小，不代表生产，压测仍待做。
- 未完成（诚实说明）：① “离线 10 分钟”用“断开连接后再重连并补齐”模拟，没有真的等 10 分钟；② 会话列表按页码翻页（IM 原生方式），翻页期间有会话变活跃时某行可能移位一格，已在契约中写明客户端按 (peer, 类型) 去重，没有做快照游标；③ 群聊会话与成员资格校验（“已不属于该用户的会话不返回”）要等群聊 Story——单聊下 IM 按用户隔离，已测；④ 墓碑清理（保留窗口）与同步分页大小的运营配置未做；⑤ 消息可见性过滤（撤回/删除墓碑，AD-4）等对应 Story 接入；⑥ 草稿冲突是“最后写入者胜”，没有合并；⑦ “回滚方案：同步游标版本化”目前只有会话游标版本化（`c1.`）。

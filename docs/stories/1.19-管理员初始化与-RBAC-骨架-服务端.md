# Story 1.19: 管理员初始化与 RBAC 骨架（服务端）

**Epic 1：账号与最小聊天纵切（可信基座）（本 Story：Phase 2）** · 规模 M（S=半天–1天，M=1–3天，L=3–7天；按单个开发 Agent 的上下文可完成估算）

As a 平台所有者,
I want 通过安装向导创建首个管理员，后台可按角色访问并查看审计日志,
So that 没有默认口令，所有管理动作可追溯.

## 验收标准（Acceptance Criteria）
**Given** 全新部署
**When** 运行安装向导
**Then** 创建首个管理员并强制设置强口令，install.lock 不作为鉴权依据

**Given** 无权限角色
**When** 调用管理接口
**Then** 返回 403，且生成式越权测试覆盖每个路由

**Given** 管理员执行高危动作
**When** 完成
**Then** audit_log 写入操作人、对象、理由与时间并可在后台只读查询

**Given** 管理员账号
**When** 首次登录
**Then** 强制绑定 TOTP 二次验证（管理面独立于用户侧 MFA）；无 MFA 的管理员无法访问任何管理接口

## 测试（含安全负面测试）
- 安全负面：默认口令/空口令/弱口令被拒；管理接口越权矩阵
- 集成：审计链头校验
- E2E：安装向导→登录→查看审计
- 安全负面：删除 install.lock 后重新初始化被拒；仅持有口令无 MFA 无法登录管理面

## Dev Agent Record
- 状态：review（服务端部分；管理面 Web 界面、安装向导界面属于 Manager 前端与 Story 1.21）。新增 `internal/admin` 模块（domain/ports/app/adapters/http）、迁移 `0008_admin`（`role`、`permission`、`admin_user`、`system_state`、`admin_challenge`、`admin_session`）、独立监听 `VG_MANAGER_ADDR`（默认 `127.0.0.1:9103`）与管理面 API（契约 `packages/contracts/openapi/manager.yaml`）、CLI `veyrogram-api admin bootstrap`、独立 Nginx 站点模板、指标 `vg_admin_denied_total` 与告警 `VeyroGramAdminProbing`。
- 设计：口令 Argon2id（参数记录在哈希里，可后续加强）；强口令策略（12–128 位、三类字符、不含用户名、不在常见口令表、不是单字符重复，空口令/默认口令/`admin`/`Password123!` 均被拒并一次列出全部违规项）；TOTP（RFC 6238，实测对齐官方测试向量，±1 步漂移，同一时间步的码不可重放，密钥 AES-256-GCM 加密落库）；登录永远两步，口令单独不产生会话，未绑定 TOTP 的管理员只能走 `mfa/enroll`，并且必须提供 bootstrap/创建者带外拿到的密钥生成的码（口令持有者无法抢先绑定自己的验证器）；错误码令牌一次性（错一次要重新输口令，限制猜码）；5 次失败锁 15 分钟；未知用户与错误口令响应完全一致并做等价耗时的哑验证（防枚举）；会话为不透明、可撤销令牌（库里只存 SHA-256），绝对 8 小时、空闲 30 分钟；禁用管理员立即撤销其全部会话；最后一个在任 owner 不可被禁用（事务内加锁，两个 owner 同时互相禁用也只会成功一个）。
- 策略引擎：每条路由必须经 `Router.Handle` 注册并声明策略（封闭词表里的权限，或显式 `Public`），缺失/未知/二者并存会在启动时 panic；测试用路由表**生成**越权矩阵（无凭据、错误方案、空/短/未知/超长/类 SQL 令牌、登录挑战令牌当会话令牌、四个角色×每条路由），所以新路由一注册就自动被覆盖；另有源码扫描测试确认包里没有绕过 Router 直接注册路由。
- 审计：创建/禁用管理员等高危动作必须带理由（≥8 字），**先**写入哈希链审计（操作人、对象、理由、时间）再执行，写不进审计则动作不发生；登录成功/失败/锁定/绑定/登出都入审计；`GET /v1/manager/audit` 只读（POST/PUT/DELETE/PATCH 均不可用）；`GET /v1/manager/audit/verify` 重算整条链，测试里直接改库里一行后验证返回 `ok:false`。
- 一次性初始化：由数据库里的 `system_state` 标记行（与第一个管理员同一事务写入）决定；测试里创建后删除 `install.lock` 再次初始化仍被拒，库里始终只有一个管理员。`install.lock` 不参与任何鉴权/初始化判断。
- 验证（真实 MySQL 8.0 + 真实二进制）：弱/空/默认口令 bootstrap 被拒且不创建任何东西；TOTP 密钥与口令均不明文落库；用户 API 监听上没有管理路由、管理监听上没有用户路由；密码登录令牌打不开任何管理接口；错码不能绑定、挑战只能用一次；已用过的 TOTP 码不能重放、下一时间步可用；创建管理员缺理由/弱口令/未知角色/重名分别 422/422/400/409；审计行记录了操作人、动作、对象、理由与时间；auditor 能读审计但管理员管理接口一律 403；禁用后其会话立即 401 且不能登录；5 次错口令后连正确口令也被拒（429 locked）且入审计；登出即失效；IP 白名单之外的地址（含登录接口）一律 403；配置守卫（缺/弱加密密钥、无数据库、非法白名单、与用户端口冲突）启动被拒；`vg_admin_denied_total` 可见；Nginx 管理面站点真 nginx 测试：只转发 `/v1/manager/`，用户 API 路径和 `/healthz`、`/metrics` 都是 404。
- 未完成（诚实说明）：① AD-3 的“高危动作需审批”（第二人确认）未做，目前是 owner + 理由 + 审计；② 管理员忘记口令/丢失验证器的恢复流程未做（建议至少保留两个 owner）；③ 管理员自助改口令、重置他人 MFA 未做；④ 登录页/管理后台界面属于 Manager 前端 Story，安装向导界面属于 1.21（本 Story 只给命令行 bootstrap）；⑤ 管理面限流是进程内存里的按地址计数（重启清零），持久的暴力破解防线是库里的账号锁定；⑥ 本机登录一次 Argon2id 约 0.1–0.2 秒，生产硬件上的耗时与参数需复测；⑦ “可选 IP 白名单/VPN”已支持，但是否启用、白名单取值需要你按网络情况决定。

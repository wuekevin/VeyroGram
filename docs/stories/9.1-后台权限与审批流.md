# Story 9.1: 后台权限与审批流

**Epic 9：管理后台商业运营能力（本 Story：Phase 3）** · 规模 L（S=半天–1天，M=1–3天，L=3–7天；按单个开发 Agent 的上下文可完成估算）

As a 平台运营,
I want 完整的角色权限与高危动作审批,
So that 最小权限，避免单人滥权.

## 验收标准（Acceptance Criteria）
**Given** 角色
**When** 分配权限
**Then** 以资源+动作授权，默认最小，变更写审计

**Given** 封号/导出/改配置/清理远程记录
**When** 发起
**Then** 进入审批并有理由字段

**Given** 管理员“代发消息/冒用身份”
**When** 默认
**Then** 关闭，开启需审批并在会话留标识

**Given** 管理员物理清理远程记录或删除消息
**When** 发起
**Then** 需要审批、理由并写审计

**Given** 删除用户消息
**When** 管理员发起
**Then** 需审批并写审计（FR-46）

## 测试（含安全负面测试）
- 安全负面：越权矩阵、审批绕过
- 审计：审批全链路可查
- E2E：申请-审批-执行

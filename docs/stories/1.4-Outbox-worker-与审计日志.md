# Story 1.4: Outbox、worker 与审计日志

**Epic 1：账号与最小聊天纵切（可信基座）（本 Story：Phase 2）** · 规模 M（S=半天–1天，M=1–3天，L=3–7天；按单个开发 Agent 的上下文可完成估算）

As a 平台所有者,
I want 事务 outbox、worker 与追加写审计日志,
So that 状态变更与事件原子提交，高危操作可追溯且不可被应用账号篡改.

## 验收标准（Acceptance Criteria）
**Given** 应用数据库账号
**When** 对 audit_log 执行 UPDATE 或 DELETE
**Then** 被数据库权限拒绝

**Given** worker 处理 outbox
**When** 同一事件被重复投递
**Then** 消费者按事件 ID 幂等，失败退避后进入死信并可重放

**Given** 审计日志
**When** 每日
**Then** 链头哈希锚定到主机外存储（对象存储版本化/WORM 或独立日志主机）

## 测试（含安全负面测试）
- 安全负面：应用账号无法改写审计；审计链头校验
- 并发：SKIP LOCKED 多 worker 无重复处理

## Dev Agent Record
- 状态：review。已完成：迁移 0002（outbox、outbox_consumed、dead_letter、audit_log、audit_head，TEXT/BLOB 无 DEFAULT，lint 通过）；`internal/platform/outbox`（同事务入队、`FOR UPDATE SKIP LOCKED` 领取、按 ordering_key 严格顺序且同键不并发、租约过期回收、按 topic 的消费者去重、退避重试、超次数进死信、`outbox replay` 重放、panic 视为失败）；`internal/platform/audit`（哈希链追加、`Verify` 从 audit_log 重算而不信任 audit_head、`AnchorHead` 仅在链完好时写出站锚点、`CheckAnchor` 比对锚点）；`db.GrantApp`（逐表授权，audit_log 仅 SELECT/INSERT；MySQL 无法从库级授权里减去表权限，所以必须逐表）；CLI：`worker`、`audit verify|anchor`、`outbox replay <id>`（并写入审计）、`db grant-app`；`veyrogram-worker.service`；`vg_outbox_pending` 指标与两条告警。
- 证据（真实 MySQL 8.0.46）：应用账号对 audit_log 的 UPDATE/DELETE/TRUNCATE/DROP/ALTER/REPLACE 均被数据库拒绝（1142/1143），对普通表仍可更新、无 DDL 权限；6 个 worker 并发 300 事件零重复；5 个 key×20 事件 4 个 worker 无乱序且同键不并发；篡改（改字段/删中间/删首行/改时间/改 prev 链接）均被 Verify 发现；尾部截断与“整条链伪造重算”Verify 发现不了，但被离线锚点发现（测试已覆盖）；变异（去掉顺序子句、去掉去重、audit_log 放开 UPDATE、跳过 prev 校验、禁用租约回收）均被测试捕获。
- 测试中发现并修复的真实缺陷：并发首次追加时 `INSERT IGNORE audit_head` 互相死锁 → 迁移预置头记录，追加只锁行。
- 未完成（诚实说明）：① “链头每日锚定到主机外存储”只实现了出站接口与 HTTPS 适配器（用本地 HTTP 服务测试），未对接真实的对象存储（版本化/WORM）或独立日志主机，也没有每日定时任务（需运维配置 systemd timer 调用 `audit anchor`，并定期用保存的锚点做 `CheckAnchor`）；② `CheckAnchor` 目前由库函数提供，尚无读取历史锚点并比对的 CLI；③ 迁移账号与应用账号分离只做了授权工具与文档，部署脚本尚未创建账号；④ worker 暂无业务 topic 处理器，topic 由后续故事注册；worker 进程没有指标监听口（`vg_outbox_pending` 由 API 进程导出）；⑤ 死信重放未做 Web/管理面入口。
- 补充（后续轮次）：① 新增 `audit check-anchors [-days N] [-require-all]`：从异地锚点库读取最近 N 天锚点并逐一与当前日志比对（尾部截断/整链重写/锚点损坏均判失败，缺失天数只报告，`-require-all` 可转为失败；0 个可验证锚点也失败）；② 新增 `db provision`：幂等创建库与 migrator/app 两个账号、改密即轮换，口令只能经环境变量传入且强度校验，真实 MySQL 测试覆盖“provision→migrate（migrator）→grant-app→app 无 DDL/不可删 audit_log→轮换后旧口令失效”；③ worker 进程新增独立内部监听（`VG_WORKER_INTERNAL_ADDR`，默认 127.0.0.1:9103，/metrics 需令牌，/readyz 查 MySQL）与 `vg_outbox_events_total{topic,result}`；④ outbox 对 MySQL 1213/1205 做有界重试（CI 上出现过一次死锁）。仍未做：锚点接真实 WORM/版本化存储及每日 systemd timer；业务 topic 的处理器与回调幂等去重（无消费者）。

# Story 1.15: 单聊消息收发（服务端与 before_send 骨架）

**Epic 1：账号与最小聊天纵切（可信基座）（本 Story：Phase 2）** · 规模 M（S=半天–1天，M=1–3天，L=3–7天；按单个开发 Agent 的上下文可完成估算）

As a 终端用户,
I want 在两位用户之间发送并接收文本消息，重试不重复、顺序不乱,
So that 最小可用的聊天闭环.

## 验收标准（Acceptance Criteria）
**Given** 客户端用 ULID 作为 client_msg_no
**When** 网络抖动导致重发
**Then** IM 按（发送者、client_msg_no、频道）只产生一条消息

**Given** 发送失败
**When** 用户查看
**Then** 显示失败状态与重试入口且不静默丢弃

**Given** 测试夹具在 IM 中写入禁言/黑名单规则
**When** 该用户经 IM 网关发送
**Then** 被 IM 原生 send_ban/黑名单拒绝；Given before_send 超时

## 测试（含安全负面测试）
- 安全负面：IM 网关直发时，IM 原生 send_ban/黑名单与 before_send 拒绝（客户端经 SDK 直连 IM 是 v1 的正常发送路径；/v1/messages/* 只承载业务扩展消息）（T-23）
- 并发：同一会话并发发送的序号单调
- 契约：客户端与 IM 的 SENDACK 错误码映射
- 故障注入：before_send 超时与业务服务不可达时受限规则 fail-closed

- **配置/决策点：** before_send 超时预算（P95 ≤50 ms，待测）与 fail-closed 规则类
- **回滚方案：** 关闭 before_send 即退回 IM 原生规则；不影响已存消息

- 状态：review（服务端部分；客户端发送失败态与重试入口属于 1.17 及各端 Story）。新增 `internal/message` 模块（domain/ports/app/adapters/http）、迁移 `0005_message_ref`、接口 `POST /v1/messages`（契约 `packages/contracts/openapi/messages.yaml`，含原因码表）、指标 `vg_message_gate_total{rule,result}`、告警 `VeyroGramSendGateFailClosed`（promtool 单测通过）。
- before_send 骨架：`Gate` 按序执行规则，整体预算 400 ms（IM 侧超时 500 ms）；**受限规则**（频道/负载/账号）出错或超时一律拒绝（原因码 200，fail-closed），**非受限规则**失败则跳过并计数，因此将来的限流投影抖动不会拖垮收发。规则：仅支持单聊（群聊在自己的 Story 里加规则，此前关闭）、发送者必须是会话参与者、负载必须是带整数 `type` 的 JSON 对象（文本非空且 ≤4000 字，总大小 ≤16 KiB，未知类型放行以便客户端降级）、发送者与对方必须是启用账号（含禁用账号 129、不存在/系统账号 130）。系统账号 `vg_system` 的发送直接放行（账号通知用，客户端无法以该 uid 登录）。拉黑/限流规则槽位已留，等对应 Story。
- 验证（真实 MySQL + 真实补丁 WuKongIM（before_send 指向真实 API 回调监听）+ 真实 WebSocket 客户端）：A 发给 B 收到；同一 client_msg_no 重发得到相同 message_id/seq 且 B 只收到一次；各拒绝原因码经 JSON-RPC error 到达客户端（130/131/132/129）；IM 原生禁言仍先于网关生效；手造的非本人会话 id 被 IM 原生拒绝（观测到原因码 15）；`POST /v1/messages` 与 WS 走同一网关，重试返回同一消息且 `message_ref` 只有一行；错误映射表单测；24 个并发发送得到 24 个连续且不重复的序号；系统通知（device_notice）在启用网关后仍能送达；业务服务不可达时 IM 拒绝发送（fail-closed）；账号规则查询出错/超时时网关拒绝（单测，含“规则忽略 context 仍按预算返回”）。
- 本机测量（不是通过门槛）：串行 60 次发送的 SENDACK 往返（IM + 同步 hook + 一次 MySQL 查询）p50≈12.6 ms、p95≈15 ms、max≈17 ms；这是单机静默环境，不能代表 NFR-9 的负载下 P95 ≤ 50 ms，仍须在真实硬件压测。

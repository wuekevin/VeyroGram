# Story 1.12: 手机号注册与登录（服务端）

**Epic 1：账号与最小聊天纵切（可信基座）（本 Story：Phase 2）** · 规模 M（S=半天–1天，M=1–3天，L=3–7天；按单个开发 Agent 的上下文可完成估算）

As a 终端用户,
I want 用手机号和一次性验证码注册并登录,
So that 快速、安全地开始使用且无法被固定验证码绕过.

## 验收标准（Acceptance Criteria）
**Given** 生产配置
**When** 请求验证码
**Then** 只发送随机一次性验证码，不存在固定值，且超限返回 429 并写风控事件

**Given** 验证码正确
**When** 登录
**Then** 创建用户与设备记录并签发短期访问令牌与轮换刷新令牌

**Given** 同一手机号/设备/IP 的连续失败
**When** 达到阈值
**Then** 延迟与设备风控生效，并写 login_event

## 测试（含安全负面测试）
- 安全负面：暴力破解、验证码重放、伪造 X-Forwarded-For
- 单元：令牌签发与轮换
- E2E：注册→登录→刷新
- 安全负面：短信轰炸（SMS pumping）与账号枚举被限频、统一响应

## Dev Agent Record
- 状态：review（服务端部分）。新增 `internal/identity` 模块（domain/ports/app/adapters/http 分层，AD-1 检查通过）、`platform/token`（Ed25519 JWS，`kid` 轮换，仅标准库）、`platform/clientip`（AD-16 可信代理）、迁移 `0003_identity`（`user`/`device`/`refresh_token`/`sms_code`/`login_event`）、契约 `packages/contracts/openapi/auth.yaml`、功能开关 `VG_AUTH_SMS_LOGIN`（关闭时路由不存在）。
- 行为：验证码 6 位 `crypto/rand` 随机、5 分钟有效、一次性、错 5 次作废、新码顶替旧码，库里只存 HMAC；手机号只存 HMAC 盲索引 + 末 4 位；请求验证码对已注册/未注册号码响应完全一致，登录失败（错码/过期/重放/从未请求）统一 401 `invalid_code`；发送限频（每号 60 秒冷却+每小时 5 次、每 IP 20、每设备 10、全局 2000，超限 429+Retry-After+`login_event`）；失败锁定（15 分钟内每号 5、每 IP 30、每设备 10 次失败 → 429 `too_many_attempts`，锁定期间正确验证码也不被接受）；X-Forwarded-For 仅在对端属 `VG_TRUSTED_PROXIES` 时按从右到左取值，伪造头不能重置限额；访问令牌 15 分钟、刷新令牌 30 天不透明单次使用并轮换，复用已轮换令牌 → 吊销该设备全部令牌并写 `reuse` 事件；`/v1/auth/*` 响应 `no-store`，且绕过幂等缓存（否则令牌会被存进库）；`login_event` 对应用账号 append-only。
- 测试（真实 MySQL 8.0 + 真实二进制）：E2E 注册→登录→刷新；多设备；明文不入库；验证码随机/重放/顶替/过期；账号枚举（响应逐字相同）；发送限频、短信轰炸（IP/设备/全局）；暴力破解与三类锁定；XFF 伪造（不可信对端与可信代理两种）；刷新复用吊销与重新登录；8 并发同一验证码只成功 1 次；禁用账号；短信网关故障返回干净 503；输入校验；令牌伪造（alg none/换算法/篡改/同 kid 异密钥/轮换/过期）；生产配置拒绝 log 通道/明文 http 网关/弱密钥/信任所有代理；应用账号对 `login_event` 只能追加。
- 未完成（诚实说明）：① 真实短信服务商（OQ-8）未接，只有通用 HTTPS JSON 网关适配器与仅限开发的日志通道，真实短信未验证（见运维清单 F）；② 访问令牌的“逐请求校验 + Redis 拒绝列表”、IM 令牌轮换、设备列表/踢出属于 Story 1.13；③ 拒绝列表/Redis 未接，吊销目前只作用于刷新令牌（访问令牌最长 15 分钟后失效）；④ 设备风控目前只有“同设备失败计数”，没有设备信誉/指纹；⑤ 过期的 `sms_code`/`login_event`/已轮换刷新令牌尚无清理任务（需保留已轮换令牌直到其原始过期以检测复用，清理策略留给 1.13/运维）；⑥ 客户端界面不属于本 Story（1.14）；⑦ 限流阈值未经真实流量校准。

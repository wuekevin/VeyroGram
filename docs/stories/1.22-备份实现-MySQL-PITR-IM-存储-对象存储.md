## Dev Agent Record
- 状态：review（Mac 上能做的已全部做完并用真实 MySQL / WuKongIM 演练；真实主机、异地存储、真实对象存储的验证见 `docs/ops/MANUAL-CHECKLIST.md` C10）。完整说明在 `infrastructure/backup/README.md`。
- 加密（AC1）：新包 `internal/platform/backupcrypt` + 子命令 `backup keygen|encrypt|decrypt`。备份在**备份主机上用公钥加密**后才落盘，私钥只在你自己的机器上生成和保存，主机被攻破既读不到已有备份也读不到将来的备份。每个文件一个随机 AES-256 密钥（RSA-OAEP 包裹），分块 AES-GCM（STREAM 构造，块序号与“最后一块”标志绑进 nonce，文件头绑进每块的附加数据）：翻转一位、调换/删除/追加块、截断、错钥全部被检出（单测逐项覆盖）。选择自己实现在二进制里而不是拼 openssl 命令，是为了密钥不出现在命令行参数里、可单测、跨平台一致。
- MySQL（AC1）：`backup.sh mysql-full`（`mysqldump --single-transaction --flush-logs --source-data=2`，不锁写入方）+ `mysql-binlog`（每 5 分钟关闭并上传已关闭的 binlog，经 `mysqlbinlog --read-from-remote-server`，只有备份账号）+ `prune`（只删已上传的本地副本）。产物 0600、目录 0700，由 `VG_BACKUP_UPLOAD_CMD` 送到主机外；**没配上传命令时运行失败**（本地备份不算备份）。新增只读备份账号 `db provision-backup`（权限已用真实 MySQL 测过：不能写、不能改表、不能授权、不能改全局变量，轮换口令后旧口令失效）。
- 恢复：`restore.sh mysql -u <UTC 时间>` 按时间点恢复；**先认证并检查全部产物（全量 + 每个 binlog + 链无缺口），再动目标**，所以坏文件不会留下半个数据库；目标库非空则拒绝；binlog 起点与库名取自**已认证的 dump 内部**，不信任无认证的清单文件（测试里篡改清单里的位置也不影响结果）。演练：真实源库 → 全量 → 变更 → 事故（`DELETE` + `DROP TABLE`）→ 恢复到事故前一刻，行数和被删的表都回来了且事故没被重放；不带 `-u` 则事故被重放；篡改/截断/缺块/错钥/覆盖非空库均被拒。
- IM（AC2）：`backup.sh im`，已验证的流程是“停 IM → 本地复制数据目录 → 立刻启动 → 再加密上传”，停机只有一次本地复制的时间（清单里记录 `downtime_seconds`），启动由 EXIT trap 保证。真实 WuKongIM 进程演练：发 25 条消息 → 硬停 → 备份 → 在“另一台机器”恢复 → 新进程读回 25 条，序号与内容一致，新消息序号继续递增。`VG_IM_QUIESCE=none`（卷快照）**没有演练过，不声称安全**。
- 对象存储（AC3）：`object-storage-setup.sh` + 备份桶/媒体桶两份生命周期策略，应用后**读回校验**版本化与规则是否真的生效（假 provider 测了：被忽略/Suspended/规则被丢都会失败）。保留天数只是默认值。
- 监控：备份时间戳/大小指标 + 告警 `VeyroGramBackupFailed` / `VeyroGramBackupStale` / `VeyroGramBackupMetricsMissing`（promtool 单测）。systemd：四个备份单元 + 定时器（已装，**未启用**，须你先配好 backup.env 与公钥）；IM 快照单元以 IM 自己的账号运行并由 polkit 规则只允许它停/启这一个单元。
- 顺带的改动：`install.sh` 增加 `veyrogram-backup` 账号、备份目录、脚本、env 模板、polkit 规则；`/opt/veyrogram` 与 release 目录改为 0755（里面没有密钥，备份账号要能运行二进制），`/etc/veyrogram` 仍 0750；`lint_infra` 不变（新单元都通过）。
- 未完成（诚实说明）：① **IM 的数据丢失窗口 = 快照间隔（默认一天）**，这是产品决定（缩短间隔/卷快照/多节点），见清单 C10-6；② **库与 IM 恢复到不同时刻后的对账脚本没写**（以 IM 序号重建 `message_ref`），跨存储恢复目前要人工核对；③ 真实异地存储、真实 provider 的版本化行为、真实主机上的 polkit/systemd 行为、真实数据量下的恢复耗时（RTO）都没有测，只能在 C10 的演练里取得；④ `mysqlbinlog --database` 对“未选库就执行的 DDL”不会重放（应用总是选库，文档已写明）；⑤ 备份主机上的活动 binlog 在关闭前不会上传，所以主机整机丢失时数据库的窗口最多约一个 binlog 间隔；⑥ 私钥丢失 = 所有备份无法读取（设计如此），清单里已强调保存两份。

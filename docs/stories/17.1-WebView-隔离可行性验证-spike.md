# Story 17.1: WebView 隔离可行性验证（spike）

**Epic 17：小程序运行时与市场（本 Story：Phase 5）** · 规模 M（S=半天–1天，M=1–3天，L=3–7天；按单个开发 Agent 的上下文可完成估算）

As a 平台工程团队,
I want 验证 iOS WKWebView 与 Android WebView 上“每应用独立 origin + 分区存储”的可行实现,
So that 把未验证假设变成已验证决策（AD-11）.

## 验收标准（Acceptance Criteria）
**Given** 两个小程序
**When** 运行
**Then** 一个读不到另一个的存储与 Cookie，或明确记录不可行及替代方案

**Given** 自定义 scheme 与独立域
**When** 导航到未声明域名
**Then** 被拦截

**Given** 平台规则
**When** 审查
**Then** 输出 App Review 与 Android 政策风险清单（OQ-OP-4）

## 测试（含安全负面测试）
- 验证：隔离用例集
- 安全负面：跨应用数据读取尝试
- 文档：结论写入 ADR-0005 更新

## 跨端任务
| 列 | 任务 |
|---|---|
| Server | 不适用：不涉及服务端变更 |
| Android | 原型容器 |
| iOS | 原型容器 |
| Web | iframe/子域验证 |
| Desktop | Electron 隔离验证 |
| Manager | 不适用：不涉及管理后台 |
| API | 不适用：不新增/变更接口 |
| DB | 不适用：不涉及数据库变更 |
| 通知 | 不适用：不触发通知 |
| 权限 | origin 与存储分区 |
| E2E | 隔离用例 |

- **回滚方案：** spike 失败则调整 AD-11 的方案

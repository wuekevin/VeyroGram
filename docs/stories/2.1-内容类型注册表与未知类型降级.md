# Story 2.1: 内容类型注册表与未知类型降级

**Epic 2：完整的消息体验（本 Story：Phase 3）** · 规模 M（S=半天–1天，M=1–3天，L=3–7天；按单个开发 Agent 的上下文可完成估算）

As a 客户端开发者,
I want 一个版本化的消息类型注册表，所有扩展消息都登记其 schema 与降级文案,
So that 新类型不会让旧客户端崩溃.

## 验收标准（Acceptance Criteria）
**Given** 新增消息类型
**When** 提交 PR
**Then** 缺少 schema、示例、各端渲染与降级文案任一项则 CI 失败

**Given** 旧版本客户端
**When** 收到未知类型
**Then** 显示“当前版本不支持该消息”而非崩溃或空白

**Given** 注册表更新
**When** 客户端启动
**Then** 能力探测返回其支持的类型版本

## 测试（含安全负面测试）
- 合约：跨端 golden 样本
- 回归：旧版本客户端收新类型
- 单元：schema 校验

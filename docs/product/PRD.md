# PRD: VeyroGram
*Working title — 品牌核验未完成（见 OQ-1）。*

## 0. Document Purpose

本 PRD 面向产品负责人、架构/安全/各端工程负责人以及后续 BMAD 工作流（UX、Architecture、Epics/Stories）。词汇以 §3 Glossary 为准；§4 按特性分组，FR 全局编号（FR-1…），并以 `Realizes UJ-N` 关联旅程；推断内容以 `[ASSUMPTION]` 标注并汇总于 §9。

本文建立在以下已存在的证据之上，不重复其内容：`BMAD-MASTER.md`（不可变约束与阶段定义）、`docs/audit/`（上游基线、功能矩阵 260 行、风险清单 30 条、现状架构、24 份官方 Swagger 索引）。官方收费模块的逐行需求以 `docs/audit/feature-matrix.csv` 为权威，本 PRD 把它们收敛成可验收的 FR，并在 `addendum.md` 保留映射。技术实现选择（协议、存储、选型）不写入本文，归 ADR 与 `addendum.md`。

## 1. Vision

VeyroGram 是一个可运营、可审计的全端即时通讯平台：Android、iOS、Web、桌面（Windows/macOS/Linux）、商业运营后台、开发者开放平台与官网共用一套品牌、协议和权限模型。它以唐僧叨叨（TangSengDaoDao）与悟空 IM（WuKongIM）为技术起点，但不是换 Logo 的二开：每一端的界面与图标须重新设计，上游缺陷（默认口令、无鉴权的 IM 内部 API、过期依赖、失效测试）须逐项修复，并以测试证据证明。

产品要同时满足三类人：日常使用者要的是消息可靠、隐私可控、跨端一致；运营方要的是可配置、可审计、可风控的后台与订阅/权益体系；开发者要的是可注册、可审核、可发布的开放平台与小程序生态。官方付费模块（收藏、位置、文件、标签、群高级管理、小视频、安全与隐私、表情商店、朋友圈、客服、旗舰、音视频）只作为**功能需求基线**，在未取得源码与合法使用权的前提下全部独立实现。

**Why now（时间敏感点）：** 官方文档/示例与上游依赖已出现明显滞后（Electron 26、React 17、Pods 无法在 Xcode 26.6 编译，WuKongIM 仍为 3.0 beta），二开必须先于规模化运营完成安全与供应链治理。

## 2. Target User

### 2.1 Jobs To Be Done
- 日常用户：在多台设备上**可靠、不丢不乱序**地收发消息、文件与通话；清楚谁能看到我的资料、动态和在线状态；设备丢失或账号泄露时能立刻止损。
- 群主/管理员：管理成员、禁言、邀请审核、历史可见性，并在争议时有可追溯的撤回与审计记录。
- 运营/客服/审核人员：在最小权限下处理举报、工单、内容审核、封禁与统计，所有高危动作有审批与审计。
- 开发者：注册主体、创建应用、拿到最小 scope 的授权、提交小程序并走审核发布与回滚。
- 平台所有者：在合规边界内上线、收费（订阅/权益）、监控、备份恢复与灰度发布。

### 2.2 Non-Users (v1)
- 需要**端到端加密（E2EE）**作为核心承诺的用户（v1 不宣称 E2EE，见 §5）。
- 需要无限成员超大群的社区场景（v1 只承诺经压测验证的上限，见 NFR-9）。
- 与 SereinGram/Telegram 客户端兼容的用户：VeyroGram 与该项目完全隔离。

### 2.3 Key User Journeys
*UJ 全局编号；FR 以 `Realizes UJ-N` 引用。*

- **UJ-1. 林夏换了新手机并恢复聊天。** [ASSUMPTION: “十分钟内”为体验目标，待度量]
  - Persona + context：林夏，自由职业者，旧手机屏幕摔坏，手上只有新手机与 SIM 卡。
  - Entry state：未登录，iOS，已在应用商店安装 VeyroGram。
  - Path：输入手机号 → 接收短信验证码 → 因设备锁开启被要求二次验证 → 在已登录的 Mac 桌面端确认新设备 → 进入会话列表。
  - Climax：会话列表与未读数、置顶/免打扰设置、草稿一次性同步到位，历史消息按需分页加载。
  - Resolution：旧设备在“设备管理”里被她远程下线，旧设备令牌随即失效。
  - Edge case：短信通道故障时，她改用 Passkey 或已信任设备确认，而不是被锁死。

- **UJ-2. 周聿在 800 人群里清理一场广告刷屏。**
  - Persona + context：周聿，社群群主，群里出现带恶意链接的广告。
  - Entry state：已登录 Android，是该群群主。
  - Path：长按消息 → 撤回成员消息 → 点成员头像对其禁言 2 小时 → 开启“邀请需确认” → 举报该账号。
  - Climax：撤回后所有成员（含离线设备）同步看到撤回提示，且被撤回内容无法通过搜索或缓存再被读取。
  - Resolution：审计日志记录谁在何时对谁做了什么；运营后台收到举报工单。
  - Edge case：周聿的管理员 B 同时撤回同一条消息，系统按幂等处理，只记录一次。

- **UJ-3. 陈岚在会议室用桌面端发起 6 人视频会议。**
  - Persona + context：陈岚，项目经理，Windows 桌面端 + 手机。
  - Entry state：已登录桌面端，已授权摄像头与麦克风。
  - Path：群聊内点击会议 → 选择入会成员 → 呼叫 → 成员接听/忙线/超时 → 会议中共享屏幕。
  - Climax：弱网下画质自适应降级而不是掉线，网络恢复后自动重连。
  - Resolution：挂断后群内出现通话记录；录制需要明确同意，默认关闭。
  - Edge case：一名成员正在另一通话中，对方看到“忙线”，陈岚看到该成员状态。

- **UJ-4. 吴迪在朋友圈只发给“同事”标签的人。**
  - Persona + context：吴迪，不想让家人看到工作动态。
  - Entry state：已登录 iOS，已建立“同事”标签。
  - Path：发布 9 张图并拖动排序 → 选择“部分可见：标签=同事” → 提醒某人查看 → 发布。
  - Climax：被排除的好友既看不到动态，也看不到点赞/评论的存在；吴迪删除动态后缓存与通知同步清除。
  - Resolution：吴迪在“新消息入口”看到同事的点赞与评论提醒。
  - Edge case：吴迪后来把某人从标签移除，该人对历史动态的可见性立即按当前规则重算。

- **UJ-5. 艾琳在开发者控制台上线一个小程序。**
  - Persona + context：艾琳，企业开发者，已完成主体认证。
  - Entry state：已登录开发者平台，已创建应用并绑定域名。
  - Path：提交小程序包 → 自动风险扫描 → 人工审核 → 灰度 10% → 全量发布。
  - Climax：用户在聊天里打开小程序，授权界面只列出最小 scope；用户随后撤销授权，下一次调用立即失败。
  - Resolution：艾琳在统计页看到调用量与错误率，并可一键回滚到上一版本。
  - Edge case：审核发现恶意 Bridge 调用，小程序被下架且已授权用户收到通知。

- **UJ-6. 客服主管孙敏处理一位未登录访客的咨询。**
  - Persona + context：孙敏，管理 12 名客服的主管。
  - Entry state：已登录 Manager，拥有客服主管角色。
  - Path：访客从官网进入咨询 → 自动按技能组分配 → 客服接待并转接 → 创建工单 → 会话结束后质检评分。
  - Climax：SLA 即将超时时主管收到提醒并可介入。
  - Resolution：绩效报表与知识库命中情况可导出（脱敏）。
  - Edge case：非工作时间访客留言转为工单，次日自动分派。

- **UJ-7. 平台运营者刘洋确认一次安全事故不会再发生。**
  - Persona + context：刘洋，平台所有者，需要对 WuKongIM 内部 API 暴露做证明。
  - Entry state：已登录 Manager 与监控平台。
  - Path：运行外部可达性检查 → 查看审计日志 → 触发备份恢复演练。
  - Climax：负面测试证明 WuKongIM 业务 API 从公网与内网非授权来源均不可达。
  - Resolution：Release Readiness 清单该项签字。

## 3. Glossary
- **用户 (User)** — 注册并通过身份验证的终端账号，一个用户有多个设备。
- **设备 (Device)** — 用户的一个登录实例，具有信任状态、令牌与最近活跃时间。
- **会话 (Conversation)** — 一个单聊或群聊的消息容器；与 WuKongIM 的“频道”概念（本文称 **IM 频道 (IM Channel)**，仅指技术对象）一一对应；产品层“**广播频道 (Broadcast Channel)**”（FR-58）是另一概念。
- **消息 (Message)** — 具有类型、版本化 schema、序号与状态的内容单元；可被编辑、撤回、转发、引用。
- **内容类型注册表 (Content Type Registry)** — 版本化的消息类型与 schema 清单；所有扩展消息必须登记。
- **好友 / 联系人 (Contact)** — 经申请确认的双向关系；联系人可打**标签 (Tag)**。
- **群 (Group)** — 多成员会话，角色为**群主 / 管理员 / 成员**。
- **动态 (Moment)** — 朋友圈中的一条发布内容，具有**可见性规则 (Visibility Rule)**。
- **收藏 (Favorite)** — 用户保存的文本/图片/文件/视频/链接条目。
- **表情包 (Sticker Pack)** — 一组可添加、排序、分享的表情。
- **客服会话 (Support Session)** — 访客与客服之间的会话，隶属**技能组 (Skill Group)**，可转为**工单 (Ticket)**。
- **管理后台 (Manager)** — 运营/风控/客服/审核使用的 Web 控制台（全文统一称“管理后台”）。
- **开发者 (Developer)** — 在**开放平台 (Open Platform)** 注册主体的个人或企业。
- **应用 (App)** — 开放平台中的实体，类型含机器人、H5 应用、**小程序 (Mini App)**、服务账号、企业内部应用。
- **Bridge** — 小程序容器与宿主 App 之间的受限 JS 接口，带 allowlist 与权限弹窗。
- **权益 (Entitlement)** — 订阅/套餐赋予用户或组织的功能与配额，由服务端强制。
- **租户 (Tenant)** — 可配置的商业扩展，指一个隔离的组织边界（v1 仅 tenant-aware 设计）。
- **IM 内核 (IM Core)** — WuKongIM，负责连接、投递与消息存储；其业务 API **仅业务服务可达，不得被客户端或公网直接访问**；客户端只经受控的连接/网关入口使用 IM 内核。
- **业务服务 (Business Service)** — Go 编写的 API/BFF 与领域服务，是调用 IM 内核的唯一入口。
- **官方付费模块基线 (Paid-Module Baseline)** — 官方功能页的逐行需求，仅作需求参考。

## 4. Features

### 4.1 账号、身份与设备
**Description:** 用户以手机号为主身份注册登录，支持多设备、可信设备、设备锁与会话撤销，可选 MFA/Passkey。所有授权在服务端完成。实现须移除上游的万能验证码与默认管理员口令。Realizes UJ-1, UJ-7.

**Functional Requirements:**

#### FR-1: 手机号注册与登录
用户可用手机号 + 一次性短信验证码注册和登录。Realizes UJ-1.

**Consequences (testable):**
- 生产配置下不存在任何固定验证码；配置项为空或固定值时服务拒绝启动。
- 同一手机号/设备/IP 的验证码请求受速率限制，超限返回 429 并写风控事件。

#### FR-2: 密码与重设
用户可设置登录密码并通过短信验证码重设；密码以 Argon2id（或合规等价 KDF）存储。

**Consequences (testable):**
- 数据库中不出现可逆或弱哈希；重设后所有其他设备会话失效。
- 连续失败达到阈值触发延迟与设备风控。

#### FR-3: 设备列表、设备锁与会话撤销
用户可查看已登录设备、开启设备锁，并远程下线任一设备。Realizes UJ-1.

**Consequences (testable):**
- 开启设备锁后，新设备登录需额外验证；被下线设备的 token 在 ≤ 60 秒内无法再用于 API 与 IM 连接。[ASSUMPTION: 60 秒为目标，待 Phase 2 测量]
- 登录异常（新设备/异地）向用户其他设备发送提醒，提醒内容不含敏感消息。

#### FR-4: 可选 MFA / Passkey
用户可启用 TOTP 或 Passkey 作为二次验证。

**Consequences (testable):**
- 启用后高危操作（改密、注销、设备锁关闭）必须二次验证。
- 丢失二次验证因子时存在书面化的恢复流程，且不能绕过设备锁。

#### FR-5: 账号注销与数据导出
用户可通过验证码注销账号并申请数据导出。

**Consequences (testable):**
- 注销后个人资料、好友关系与会话入口被销毁或匿名化，保留项（审计/法定）在隐私政策中列明。
- 数据导出任务异步完成，产物受签名下载保护并带过期时间。

### 4.2 即时消息核心
**Description:** 提供文本、图片、语音、名片、系统消息，输入状态，会话置顶/免打扰，历史记录，引用回复、转发/合并转发、草稿跨设备、编辑与撤回。消息具有幂等、顺序、ACK 与离线同步语义。Realizes UJ-1, UJ-2.

**Functional Requirements:**

#### FR-6: 可靠投递与幂等
同一条消息被客户端重试发送时只产生一条记录，接收端按会话内严格序号展示。

**Consequences (testable):**
- 断网重连后重发，服务端按客户端消息 ID 去重；会话内序号无倒序且无重复。
- 发送失败有可见状态与重试入口；失败不静默丢弃。

#### FR-7: 离线同步与多端一致
用户在任意设备上线后获得离线期间的消息、会话状态与草稿。Realizes UJ-1.

**Consequences (testable):**
- 新设备首次登录后按游标分页同步，未读数与置顶/免打扰与旧设备一致。
- 草稿在设备间 ≤ 5 秒同步。[ASSUMPTION]

#### FR-8: 消息类型与内容类型注册表
所有消息类型（含扩展）在内容类型注册表登记，schema 版本化，旧客户端收到未知类型时优雅降级。

**Consequences (testable):**
- 新增类型必须附 schema、示例、各端渲染与降级文案；缺任一项 CI 失败。
- 旧版本客户端展示“当前版本不支持该消息”而不是崩溃或空白。

#### FR-9: 引用、转发、合并转发、删除范围
用户可引用回复、逐条或合并转发，并选择仅自己或双方删除。

**Consequences (testable):**
- 合并转发中的原消息权限独立校验：转发人无权访问原内容时不得转发。
- “对所有人删除”遵守时限与群角色规则，操作写入审计。

#### FR-10: 撤回与编辑一致性
发送者可在配置时限内撤回或编辑消息；所有设备（含离线）最终一致。Realizes UJ-2.

**Consequences (testable):**
- 撤回后服务端拒绝返回原内容（接口、搜索、预览均不返回）；已签发的下载 URL 在其 TTL（≤ 5 分钟）内失效，敏感内容走 API 代理下载则立即失效。
- 编辑保留版本策略（配置：保留所有版本/仅保留最新）并在界面标注“已编辑”。

#### FR-11: 输入状态、系统消息与扫码
会话显示“正在输入”；二维码可用于加好友/入群，扫码结果需用户确认。

**Consequences (testable):**
- 二维码带过期与撤销能力，过期码不可用。
- 扫码入群遵守群邀请确认设置。

#### FR-61: 个人资料与通用设置
用户可编辑头像、昵称、签名等资料，并设置语言、主题（明/暗）、字体大小与通知偏好。

**Consequences (testable):**
- 资料变更在所有设备同步；头像等图片经格式与大小校验。
- 语言与主题切换无需重启，至少支持简体中文与英文。

#### FR-64: 群创建与成员管理基础能力
用户可创建群、邀请成员、退出群、编辑群名称与群公告，发布“@成员/@所有人”提醒（@所有人受群角色限制）。

**Consequences (testable):**
- 群公告变更对所有成员产生系统消息与未读提醒；仅群主/管理员可修改。
- @所有人受频率与角色限制；被 @ 的成员免打扰期间仍显示会话内醒目标记。

#### FR-65: 语音、名片与链接预览
用户可发送语音消息、分享用户名片，消息中的链接与手机号可识别并提示操作。

**Consequences (testable):**
- 链接预览由服务端受限抓取：禁止内网/回环/元数据地址（SSRF 防护）、限制重定向与大小、超时 ≤ 5 秒。[ASSUMPTION]
- 语音消息显示时长，按下录制过程可取消，权限被拒有引导。

#### FR-66: 清空聊天记录与服务端删除范围
用户可清空本地会话；管理员/运营按审批流清理远程记录，遵守保留策略。

**Consequences (testable):**
- 清空本地不影响其他成员与服务端保留策略；远程清理需审批并留审计。

#### FR-67: Web/桌面登录与设备批准
Web 与桌面端支持手机扫码登录、验证码登录，并可由已信任设备批准新设备。Realizes UJ-1.

**Consequences (testable):**
- 扫码登录二维码一次性、带过期，批准页展示设备与位置并要求确认。
- 未被批准的会话不能读取历史消息。

### 4.3 联系人与社交关系
**Description:** 好友申请、通讯录匹配（需明示同意）、黑名单、联系人标签与批量整理，标签跨设备同步，批量行为有限制。Realizes UJ-4.

**Functional Requirements:**

#### FR-12: 好友申请与黑名单
用户可发起、接受、拒绝好友申请，拉黑后对方无法发起会话或查看资料。

**Consequences (testable):**
- 被拉黑方发送消息返回统一的失败状态，不泄露“被拉黑”。
- 黑名单变更实时作用于消息、群邀请与动态可见性。

#### FR-13: 通讯录匹配
用户可显式授权后用通讯录匹配好友；用户可关闭“按手机号被搜索”与“短号被搜索”。

**Consequences (testable):**
- 未授权通讯录权限时功能降级，不循环弹窗。
- 通讯录原始数据不落盘明文；匹配使用哈希/受限接口并限频。

#### FR-14: 联系人标签（官方付费模块基线）
用户可创建、重命名、删除标签，批量为联系人打标签，标签跨设备同步。Realizes UJ-4.

**Consequences (testable):**
- 标签仅对本人可见；服务端对象级校验防越权读取他人标签。
- 批量操作有数量上限与限速，超限返回明确错误。

### 4.4 群聊与高级群管理（付费模块基线）
**Description:** 群主/管理员/成员三类角色；邀请确认、全员/个人禁言及时长、群黑名单、禁止互加好友、新成员历史可见性、群头像、群公告、撤回成员消息。Realizes UJ-2.

**Functional Requirements:**

#### FR-15: 群角色与权限
群主可指派/撤销管理员，所有群管理动作由服务端按角色校验。

**Consequences (testable):**
- 绕过客户端 UI 直接调用接口的越权请求被拒绝并记审计。
- 群主转让需二次确认并通知全体管理员。

#### FR-16: 邀请确认与群黑名单
群可开启“邀请需确认”；群主/管理员可将成员加入群黑名单。

**Consequences (testable):**
- 黑名单成员无法再被邀请或通过二维码入群。
- 待确认邀请有过期时间与通知。

#### FR-17: 禁言（全员/个人/时长）
群主/管理员可全员禁言，或对个人禁言并设置时长。Realizes UJ-2.

**Consequences (testable):**
- 禁言期间发送被服务端拒绝，UI 同步提示剩余时长。
- 禁言到期自动恢复，且在多设备一致。

#### FR-18: 历史可见性与互加好友限制
群可设置“新成员可否查看入群前历史”与“禁止群内互加好友”。

**Consequences (testable):**
- 关闭历史可见时，新成员无法通过任何接口取得入群前消息。
- 禁止互加开启后，来自群的好友申请入口隐藏且服务端拒绝。

#### FR-19: 撤回成员消息与群审计
管理员可撤回成员消息，所有群管理动作进入可查询审计。Realizes UJ-2.

**Consequences (testable):**
- 审计记录含操作者、对象、时间、原因，不可被普通管理员删除。
- 大群（见 NFR-9 上限内）撤回在 5 秒内扩散到在线成员。[ASSUMPTION]

### 4.5 收藏（付费模块基线）
**Description:** 收藏文本/图片（可扩展文件、视频、链接），列表、复制、缩放、转发给朋友、删除，跨设备同步。

#### FR-20: 消息收藏与管理
用户可从消息菜单收藏文本/图片，并在“我的收藏”查看（含作者、昵称、收藏时间）、删除、转发、复制文本、缩放图片。

**Consequences (testable):**
- 收藏仅本人可读；被源会话撤回的消息，收藏副本按策略（保留/标记）处理并有书面说明。
- 收藏列表在多端同步，删除传播 ≤ 10 秒。[ASSUMPTION]

### 4.6 位置（付费模块基线）
**Description:** 发送当前位置或地图选点、搜索地点、查看位置卡片与缩略图、跳转地图；地图 Provider 可配置。

#### FR-21: 位置消息
用户可发送当前位置或搜索选点，接收方看到位置截图卡片并可跳转地图。

**Consequences (testable):**
- 仅在用户操作时请求前台定位权限，不默认后台定位。
- 地图 Provider 通过配置切换，缺失 Provider 密钥时入口隐藏而非崩溃。

### 4.7 文件（付费模块基线）
**Description:** 文件消息（格式/大小/名称）、上传下载（必要时断点续传）、预览、转发；类型/大小/扩展名校验、病毒扫描、签名 URL、配额与保留策略。

#### FR-22: 文件上传、下载与预览
用户可发送文件并预览常见类型，接收方可下载与转发。

**Consequences (testable):**
- 上传按 MIME+魔数+扩展名三重校验，危险类型被拒；大小/频率超限返回明确错误。
- 下载使用带过期的签名 URL（TTL ≤ 5 分钟）；会话成员资格被移除后无法再签发新 URL，已签发 URL 在 TTL 内失效，敏感内容走 API 代理下载则立即失效。

#### FR-23: 病毒扫描与隔离
文件在可下载前经过扫描；命中的文件被隔离并通知发送者。

**Consequences (testable):**
- 扫描引擎不可用时文件保持“待检”，不默认放行。[ASSUMPTION: 具体策略待 OQ 确认]
- 隔离文件可被审核后台查看元数据而非正文。

### 4.8 小视频（付费模块基线）
#### FR-24: 录制/选择、转码、播放与转发
用户可录制 15 秒（上限可配置）或选择相册视频发送；接收方显示大小、下载进度后播放、保存、转发。

**Consequences (testable):**
- 服务端转码并生成封面；失败时发送者看到可重试的明确状态。
- 编解码许可与版权在 `license-and-ip.md` 登记（见 OQ-6）。

### 4.9 表情商店（付费模块基线）
**Description:** 系统 Emoji、收藏表情、自定义表情、平台表情包（搜索、添加、详情、移除、排序）。菜单图标不使用 Emoji，聊天内 Emoji 属于内容。

#### FR-25: 表情面板与表情包管理
用户可在消息面板切换 Emoji/收藏/表情包，添加/移除/排序表情包，制作并整理自定义表情。

**Consequences (testable):**
- 自定义表情经内容审核后才可被他人使用；违规可下架。
- 平台表情包支持管理员上传、搜索、详情页添加、用户分享，并登记版权来源与授权期限；表情商店列表含搜索入口、Emoji 分类、收藏分类（首项为“制作表情”）。
- 表情包在各端按同一素材规范渲染（像素差异以视觉回归阈值为准），旧端对动图降级为静态图。[ASSUMPTION: 阈值待设计系统定义]

### 4.10 朋友圈 / 动态（付费模块基线）
**Description:** 文本/最多 9 图（可拖动排序）/单视频，位置，提醒某人，四种可见性（公开/私有/部分可见/不给谁看），评论点赞，封面，新消息入口。Realizes UJ-4.

#### FR-26: 发布与可见性
用户可发布动态并选择可见性规则，部分可见/不给谁看可从通讯录或标签选人。Realizes UJ-4.

**Consequences (testable):**
- 越权测试：被排除者不能通过 ID 直接访问动态、点赞、评论或媒体 URL。
- 可见性在标签/好友关系变化后按当前规则重新计算。

#### FR-27: 评论、点赞与提醒
好友可对可见动态评论点赞，被提醒的好友收到通知。

**Consequences (testable):**
- 只有对该动态可见且互为好友的人能看到彼此的评论与点赞。
- 用户可点击发布者头像查看其朋友圈（仅限对自己可见的动态）；列表显示发布者备注名优先、头像、发布时间、地址；长按文本可复制/收藏，长按图片可转发/收藏/保存，设置相册封面，朋友圈新消息入口汇总提醒。
- 删除动态后评论、点赞、缓存与通知同步清除。

#### FR-28: 动态审核与举报
用户可举报动态，运营后台可审核、下架。

**Consequences (testable):**
- 下架内容对所有人立即不可见并写审计；申诉流程可用。

### 4.11 安全与隐私中心（付费模块基线）
#### FR-29: 隐私设置
用户可控制：手机号/短号可搜索、在线状态与最近在线展示、已读回执开关、截屏通知开关。

**Consequences (testable):**
- 每项隐私设置由服务端强制，客户端无法绕过。
- 变更立即生效并在所有设备同步。

### 4.12 旗舰消息能力（付费模块基线）
#### FR-30: 已读/未读与成员详情
会话可显示已读/未读标记及成员详情，并可开关。

**Consequences (testable):**
- 关闭已读回执的用户不产生对方可见的已读状态，且不能反推他人状态。
- 大群已读详情按成员上限分页，超限有降级说明。

#### FR-31: 消息点赞与在线状态
用户可对消息点赞并查看点赞列表；展示在线状态/最近在线。

**Consequences (testable):**
- 遵守 FR-29 隐私设置；对方关闭展示时不泄露。

#### FR-32: 图片编辑
发送图片前可涂鸦、裁剪、加文字、加滤镜。

**Consequences (testable):**
- 编辑在本地完成，原图元数据（含位置）发送前可选择移除。

#### FR-33: 历史消息查找
用户可按日期、成员、类型、关键词在会话内查找历史。

**Consequences (testable):**
- 搜索结果严格受会话读取权限约束（被移除成员、被撤回内容不出现）。
- v1 关键词搜索在客户端本地已同步历史上执行，服务端不保存消息正文索引；服务端索引需先通过隐私评审（见 ADR-0010）。[ASSUMPTION: 评审后再定]

#### FR-34: 截屏通知与撤回通知
在操作系统实际支持的平台上，截屏可在会话内产生系统通知；撤回会产生撤回提示。

**Consequences (testable):**
- 产品界面明确标注“并非所有平台/场景可检测截屏”，不保证全面检测。
- 在系统实际支持的平台上可拦截/感知截屏并发送截屏消息（可由会话设置开关）；不支持的平台隐藏该选项并说明替代交互。

### 4.13 音视频（付费模块基线）
**Description:** 一对一与群/会议音视频，呼叫/接听/挂断/忙线/超时，前后台切换，断网重连，弱网自适应，系统电话集成（按权限），录制需明确同意。以 WebRTC 为目标，TURN/STUN 与 SFU 选型走 ADR。Realizes UJ-3.

#### FR-35: 一对一音视频通话
用户可发起/接听/挂断通话，处理忙线与超时。

**Consequences (testable):**
- 对方忙线、无应答、拒绝均有明确状态与通话记录。
- 通话令牌/TURN 凭据由服务端短时签发，不得写死在客户端。

#### FR-36: 群通话与会议
群成员可发起会议，多人入会，可共享屏幕（桌面端）。Realizes UJ-3.

**Consequences (testable):**
- 弱网下优先降低视频质量保音频；恢复后自动重连。
- 录制默认关闭，开启需所有参与者明确同意并有可见标识。

#### FR-37: 系统集成与权限
通话遵守各平台前后台/来电集成与摄像头麦克风权限。

**Consequences (testable):**
- 权限被拒时给出引导而不是静默失败。

### 4.14 客服（官方标注“开发中”，需从零做完整闭环）
**Description:** 官方仅列 6 项能力；VeyroGram 交付完整闭环：访客入口、技能组/队列、自动/手动分配、转接、SLA、工单、快捷回复、知识库、绩效、用户标签、质检、审计、工作时间。官方 Swagger 已有 `hotline` 规范（55 个操作），可作契约参考。Realizes UJ-6.

#### FR-38: 访客入口与自动分配
访客（登录或未登录）可发起咨询，系统按技能组与负载自动分配客服。Realizes UJ-6.

**Consequences (testable):**
- 通讯录内存在专属客服入口，客服与访客身份有明确标记；访客发送消息按技能组自动匹配客服，客服可设置欢迎词并查看访客资料详情与用户标签；主管可手动分配与改派。
- 非工作时间访客留言转工单。

#### FR-39: 转接、SLA 与工单
客服可转接、创建工单；系统按 SLA 计时并在临界点提醒主管。

**Consequences (testable):**
- 转接保留完整上下文与权限边界；跨租户/跨技能组不泄露会话。
- SLA 指标按会话/工单可统计并可导出（脱敏）。

#### FR-40: 知识库、快捷回复、质检与绩效
客服可使用快捷回复与知识库；主管可抽检质检并查看绩效。

**Consequences (testable):**
- 质检与导出操作写审计；客服只能访问其技能组范围内的会话。

### 4.15 搜索与媒体中心
#### FR-41: 全局搜索与媒体中心
用户可搜索联系人/群/消息/文件，并在会话内查看图片、视频、文件、链接的媒体中心。

**Consequences (testable):**
- 搜索权限与消息读取权限一致（权限矩阵测试通过）。
- 先用 MySQL/IM 内建能力，性能不达标且经评审后再引入搜索引擎。

#### FR-62: 对象存储生命周期与清理
附件、头像、媒体存放于 S3 兼容对象存储，支持缩略图/预览、访问控制、保留与清理策略。

**Consequences (testable):**
- 会话/动态被删除后，关联对象按策略在配置期限内被清理，且期间不可通过旧 URL 访问。
- 存储提供方可切换（OSS/COS/S3/自建）而不改业务代码。

### 4.16 通知与推送
#### FR-42: 多通道推送
系统通过 APNs、FCM 与适用的 Android 厂商通道推送；支持前后台/静默/免打扰与多设备冲突消解。

**Consequences (testable):**
- 通知正文不含敏感消息内容（可配置为“你有一条新消息”）。
- 一个设备已读后其他设备清除对应通知。

### 4.17 内容安全、举报与风控
#### FR-43: 举报与申诉
用户可举报用户/群/消息/动态；被处置用户可申诉。

**Consequences (testable):**
- 举报进入后台工单并可追踪状态；申诉有独立审核人。

#### FR-44: 反垃圾与账户/设备/IP 风控
系统对恶意链接、危险文件、群发和异常登录做检测与限速，策略可配置。

**Consequences (testable):**
- 命中规则写风控事件并可复核；误伤有解除流程。
- 真实 IP 只信任可信代理列表中的转发头。

### 4.18 管理后台（Manager）
**Description:** 全新企业 SaaS 风格后台：概览、用户/设备/群/消息索引、风控举报、内容审核、客服工单、媒体、活动、支付/订阅、开发者与小程序审核、数据报表、系统配置、RBAC、审批、审计。官方手册显示上游后台缺少权限矩阵与审计说明，必须补齐。

#### FR-45: RBAC 与最小权限
后台权限基于角色与资源动作授权，默认最小权限。

**Consequences (testable):**
- 任一管理接口在无权限时返回 403，并有自动化越权测试。
- 超级管理员初始化通过安装向导完成，不存在默认口令。

#### FR-46: 高危操作审批与审计
封号、删除消息、导出数据、改配置等高危动作需审批（按配置），全部写不可篡改审计。

**Consequences (testable):**
- 审计日志对普通管理员只读；导出/查看聊天记录有理由字段并留痕。
- 管理员“代发消息/冒用身份”类能力默认关闭，开启需审批且在会话内留标识。

#### FR-72: 索引查询、审核队列与统计报表
后台可按用户/设备/群/消息建立受限索引查询，提供通用内容审核队列与数据报表；消息与媒体保留策略可配置。

**Consequences (testable):**
- 查询与导出需理由字段并留痕；保留到期的数据按策略清理，清理动作可审计。
- 报表指标口径与脱敏规则文档化。

#### FR-47: 运营配置与版本更新
后台可配置功能开关、应用下载链接、版本更新与公告。

**Consequences (testable):**
- 配置变更有版本历史与回滚；每页具备 Loading/Empty/Error 状态。

### 4.19 开放平台与小程序（独立产品）
**Description:** 开发者注册（个人/企业）、团队与角色、AppID/密钥生命周期、OAuth 2.1 风格授权（Authorization Code + PKCE）、REST/OpenAPI、SDK、Webhook、应用类型、小程序运行时（受限 WebView + Native Bridge）、市场、审核、灰度、回滚、投诉。Realizes UJ-5.

#### FR-48: 开发者账号与应用生命周期
开发者可注册主体、创建应用并绑定域名/包名，密钥可轮换与吊销。

**Consequences (testable):**
- App Secret 仅创建时展示一次；轮换后旧密钥在宽限期后失效。

#### FR-49: OAuth 授权与最小 scope
用户授权时看到最小 scope 清单，可随时撤销。Realizes UJ-5.

**Consequences (testable):**
- 回调 URL 白名单校验；授权码一次性且带 PKCE；撤销后访问令牌在 ≤ 60 秒内失效且后续调用返回 401。[ASSUMPTION: 60 秒为目标，与 SM-6 一致]

#### FR-50: 小程序运行时与 Bridge
小程序运行于受限容器，Bridge 提供带 allowlist 的能力（登录授权、资料授权、分享、扫码、文件选取、位置、剪贴板、订阅消息、主题）。

**Consequences (testable):**
- 每个能力需显式用户授权；未声明域名/origin 的请求与导航被拦截；Bridge 消息带 nonce 与签名。
- 不同小程序的存储与网络隔离，容器应用 CSP 与资源上限；Android/iOS/Web/桌面运行时能力差异以“能力探测”暴露并有降级。
- 恶意小程序测试集（XSS、越权 Bridge、SSRF）全部被拦截是上线硬门槛。

#### FR-51: 审核、灰度、发布与回滚
小程序包签名后经自动扫描与人工审核，按比例灰度，可一键回滚与下架。Realizes UJ-5.

**Consequences (testable):**
- 回滚后所有端在下一次打开时使用上一版本；被下架应用对已授权用户通知。

#### FR-52: Webhook 与开放 API
开发者可订阅事件，Webhook 带签名+时间戳+重放防护+重试死信；开放 API 有速率限制与调用统计。

**Consequences (testable):**
- 重放过期时间戳的请求被拒；投递失败进入死信并可手动重放。

#### FR-71: SDK、沙箱与团队协作
开放平台提供 TypeScript/Go/Android/iOS SDK、沙箱与测试账号、调试日志，以及开发者团队与角色管理。

**Consequences (testable):**
- SDK 版本化并带兼容窗口；沙箱数据与生产严格隔离。
- 团队角色（所有者/管理员/开发者/只读）由服务端授权，变更留审计。

#### FR-53: 机器人与服务账号
可配置机器人与服务账号，可通过开放 API 收发消息并受权限边界约束。

**Consequences (testable):**
- 机器人只能访问被授权会话；不得通过内部 IM 接口直发。

#### FR-63: 小程序市场与发现
用户可浏览、搜索、查看详情与评价、收藏与查看使用历史，并可举报小程序。

**Consequences (testable):**
- 下架或被风险扫描判定恶意的小程序不出现在列表与搜索中。
- 评价与举报受速率限制，防刷评。

### 4.20 订阅、权益与支付（P1）
**Description:** VIP/订阅、权益服务（功能开关与配额）、优惠券、订单、退款、发票/税务对接、对账。支付走合规第三方，服务端验签与 Webhook 幂等，不保管银行卡敏感数据。支付服务商未定（OQ-3）。

#### FR-54: 权益与配额
系统按套餐赋予权益（如文件配额、群人数上限、AI 功能），服务端强制。

**Consequences (testable):**
- 权益变化实时生效且可审计；客户端无法本地开启付费功能。

#### FR-55: 订单、支付回调与对账
订单状态机覆盖创建/支付/退款/关闭；回调验签且幂等。

**Consequences (testable):**
- 重放回调不重复入账；日终对账差异可见并有处理流程。

### 4.21 官网、下载与更新
#### FR-56: 官网与下载中心
官网展示产品价值、跨端下载、功能、安全隐私、版本公告、FAQ、开发者入口、状态/帮助、法务页面，并支持国际化。

**Consequences (testable):**
- 下载链接与版本由后台配置；官网满足 SEO、性能与无障碍基线（WCAG 2.1 AA 目标）。
- 隐私政策与条款在发布前由法务确认（OQ-4）。

#### FR-57: 客户端更新与灰度
各端支持版本检查、强制/可选更新与灰度，桌面端更新带签名校验。

**Consequences (testable):**
- 签名不匹配的更新包被拒绝；强制更新提供过渡窗口与说明。

### 4.22 增长与扩展（P1/P2，PRD 内仅定义边界）
#### FR-58: 频道/广播与运营消息
支持频道、广播、公告号与运营消息模板、分群触达与退订。

**Consequences (testable):**
- 用户可退订运营消息；触达记录可审计。

#### FR-59: AI 辅助（翻译/总结/客服建议）
AI 功能默认关闭，需用户明确同意，经模型无关网关调用，并有成本与速率限制。

**Consequences (testable):**
- 私聊内容不默认发送给第三方模型；同意记录可查询、可撤回。

#### FR-60: 企业组织与租户（tenant-aware 设计）
v1 完成 tenant-aware 数据与权限设计，不交付“假多租户”；组织通讯录/部门/企业空间按设计验收后再排期。

**Consequences (testable):**
- 设计评审通过前不得对外宣称多租户；隔离方案经测试后决定共享库或物理隔离。

### 4.23 品牌、设计系统与跨端体验
**Description:** 所有端使用统一的 VeyroGram 品牌与原创设计系统，先出高保真关键流程原型并审批后再编码；图标为原创 SVG 图标库。

#### FR-68: 设计系统与原创图标库
提供色彩/排版/间距/形状 tokens（明暗主题）、组件库与 24px 基准的原创 SVG 图标库（含状态集与无障碍描述）。

**Consequences (testable):**
- 导航、工具栏、底部 Tab、后台菜单中**不出现 Emoji 图标**（自动化扫描门禁）；聊天内容中的 Emoji 不受限。
- 设计 tokens 由单一来源生成各端资源；UI 不允许保留上游页面样式。

#### FR-69: 多平台品牌资产与视觉回归
依据 `brand/source/logo.png` 输出 Android 自适应图标、iOS AppIcon/Launch、Web/PWA 图标与 OG 图、桌面 ICO/ICNS/PNG 与托盘图标、各端 SVG Logo；关键屏幕建立 360/390 手机、平板、桌面断点的截图基线。

**Consequences (testable):**
- 无矢量源时由手工重绘 SVG，不得由 PNG 放大冒充；图标在小尺寸可读性经检查。
- 视觉回归覆盖明/暗主题、中/英文、字体放大、空/错/加载状态。

#### FR-70: 桌面端专属体验
Web/桌面提供三栏响应式布局、快捷键、窗口拖拽、托盘、文件拖拽、系统通知、离线/恢复/更新与权限告知，而非放大的手机页。

**Consequences (testable):**
- Electron 禁用 nodeIntegration、启用 contextIsolation、IPC allowlist、外部链接校验与签名更新（见 NFR-13）。

## 5. Non-Goals (Explicit)
- 不复制、反编译或绕过官方闭源付费模块；不使用其源码或素材。
- v1 **不宣称 E2EE、绝对安全、无限群成员、全端功能一致、性能指标已达标**（未经审计不声明）。
- 不与 SereinGram/Telegram 项目共用仓库、配置、API ID、URL Scheme 或技术假设。
- 不把上游 UI 换主题后当作重设计；不在导航/菜单/Tab/后台图标中使用 Emoji。
- 不在正式部署使用 Docker/Compose；不引入额外中间件除非有压测证据。
- 不自研密码学；不自行保管银行卡信息。
- 不做“假多租户”。

## 7. Success Metrics
*所有数值均为验收目标，不是已达成声明；基线需在 Phase 2 测量。*

**Primary**
- **SM-1**：消息投递成功率与 P95 端到端延迟（负载条件：在 NFR-9 的 1k 并发连接阶梯、单聊为主、同区域测试环境下记录硬件与流量模型）。目标：成功率 ≥ 99.9%，P95 ≤ 1s。[ASSUMPTION] Validates FR-6, FR-7.
- **SM-2**：核心 E2E 通过率（注册/登录/收发/离线同步/撤回/群管理）。目标：100% 通过方可进入下一阶段。Validates FR-1…FR-19.
- **SM-3**：高危/严重安全问题数。目标：0（上线门禁）。Validates FR-1…FR-5, FR-45, FR-46.
- **SM-4**：官方付费模块逐行覆盖率（feature-matrix 付费 121 行）。目标：关闭 Epic 时 100% 行为 `TESTED`。Validates FR-14…FR-40.

**Secondary**
- **SM-5**：崩溃率（移动端）。目标：崩溃自由用户 ≥ 99.5%。[ASSUMPTION] Validates 各端交付。
- **SM-6**：开放平台示例小程序从提交到上线的闭环成功，撤权生效时间 ≤ 60 秒。[ASSUMPTION] Validates FR-49…FR-51.
- **SM-8**：连接恢复时间（断网 30 秒后恢复，P95）与关键 API（登录、会话列表、消息同步）P95 延迟，目标 ≤ 5s 与 ≤ 300ms。[ASSUMPTION，须按 NFR-9 负载条件度量] Validates FR-6, FR-7.
- **SM-7**：备份恢复演练达成 RPO/RTO 目标（目标值待 OQ-7）。Validates NFR-6.

**Counter-metrics (do not optimize)**
- **SM-C1**：不为压低“举报处理时长”而自动驳回举报。Counterbalances SM-3, FR-43.
- **SM-C2**：不为提高投递成功率而静默丢弃失败消息的可见状态。Counterbalances SM-1.
- **SM-C3**：不为提升在线时长/活跃而降低隐私默认值。Counterbalances FR-29.

## 8. Cross-Cutting NFRs

- **NFR-1 授权**：所有关键业务能力须服务端对象级授权；UI 隐藏不算授权。
- **NFR-2 IM 内核隔离**：IM 内核业务 API（含 `/message/send`、`/user/token`）仅业务服务可达，公网与非授权内网来源均不可达；有负面测试（对应 R-21）。
- **NFR-3 凭据与默认值**：生产环境无默认/弱口令、固定验证码、写死 TURN/推送密钥；密钥来自受保护环境并可轮换，日志脱敏（对应 R-02/03/20/24）。
- **NFR-4 传输与数据**：客户端与服务端、IM 连接均 TLS；MySQL 8.0 为主库、Redis 7.x 为会话/限流/缓存（用户决策：不要求 Redis 8）；敏感数据加密与保留策略明确。
- **NFR-5 供应链**：锁定依赖、禁用第三方镜像 URL、SBOM 与许可证扫描纳入 CI；高危依赖漏洞阻断发布（对应 R-12/13/28）。
- **NFR-6 可靠性与灾备**：RPO/RTO 可配置并经演练验证；数据库 PITR、对象存储版本与生命周期、备份加密。
- **NFR-7 可观测性**：指标、日志、追踪覆盖投递延迟、连接数、成功率、推送、文件失败率、支付对账、风控与开放 API 错误率；告警可用。
- **NFR-8 可访问性与国际化**：全部客户端（Android/iOS/Web/桌面/管理后台/开发者平台/官网）以 **WCAG 2.1 AA** 为验收标准：发布前须逐条完成 `docs/design/WCAG-2.1-AA-CHECKLIST.md`（50 条），含读屏（VoiceOver/TalkBack）、键盘、200% 字号与 320px 回流的人工测试记录；首个公开发布前委托第三方审计。**未完成清单与测试记录前不得宣称合规。** 至少简体中文与英文，暗色主题。
- **NFR-9 规模与性能**：以 1k→10k→更高连接逐级压测，记录硬件与流量模型；群成员上限以压测结论为准，不预先承诺。
- **NFR-10 部署**：原生 Linux + systemd + Nginx（宝塔管理），非 root 服务账号，健康/就绪探针，灰度与回滚脚本；`install.lock` 不得作为唯一鉴权依据。
- **NFR-11 许可证合规**：保留 Apache-2.0 署名与 NOTICE；Manager/Web 无许可证一项由用户**书面接受风险**（不阻断开发，但随发布留存风险记录，并在重设计中尽量不复用其业务代码）；@fancyapps/ui 须在发布前购买授权或替换（阻断项）。
- **NFR-12 API 契约**：外部接口 OpenAPI 3.1、版本化、错误码、限流、幂等、追踪 ID、游标分页；兼容窗口与迁移回滚书面化。

- **NFR-13 Web/Electron 安全**：CSP、XSS/CSRF/SSRF 防护、依赖完整性（SRI/锁文件）、禁用 nodeIntegration、contextIsolation、安全 preload、IPC allowlist、外部链接校验、签名更新；升级 Electron/React 至受支持版本（对应 R-05）。
- **NFR-14 移动端安全**：令牌存入系统安全存储，证书校验，敏感数据排除系统备份，截屏与越狱/root 风险按系统能力与策略提示。
- **NFR-15 令牌与连接**：IM 连接令牌有生命周期、绑定设备、可吊销；WebSocket/TCP 仅经 TLS；客户端不持有长期通用凭据。
- **NFR-16 端口与管理面暴露**：对外仅暴露必要 HTTPS/WSS；WuKongIM 内部 API、管理端口、监控、adminer、MinIO 控制台均不对公网开放，需认证（对应 R-08/R-21/R-22/R-23）。
- **NFR-17 安全质量门禁**：SAST/DAST/SCA/secret scan/SBOM/license scan/fuzz/race 纳入 CI；高危/严重漏洞阻断上线；OWASP ASVS/MASVS 基线用例通过。
- **NFR-18 威胁建模**：建立 STRIDE 威胁模型、资产/信任边界、数据流与 abuse-case，覆盖登录/短信、设备绑定、WebSocket 令牌、IM 内核与 Webhook 信任、消息越权、文件访问、管理后台、机器人 API、小程序 Bridge 与支付。

## 9. Constraints and Guardrails
- **隐私**：不默认永久保存所有私聊内容并宣称合规；管理员访问聊天内容需理由与审计；未成年人保护策略待法务（OQ-4）。
- **成本**：优先模块化单体，避免过早微服务与额外中间件。
- **平台规则**：iOS App Review 与 Android 平台规则对小程序、推送、录制与权限的约束须在设计阶段审查。
- **品牌**：统一 VeyroGram；与 VeyroGrama(SereinGram 系)为两个隔离产品，发布前核验包名/域名/商标。

## 10. Open Questions
*商业与法务决策，附备选与影响。*

1. **OQ-1 品牌核验**：包名/域名/商标/应用商店名称是否冲突？备选：继续使用 VeyroGram 并加区分后缀；或更换名称。影响：应用 ID、URL Scheme、签名与发布。
2. **OQ-2 地图 Provider**：高德/腾讯/Google/Mapbox？影响：位置模块密钥、合规与地区可用性。
3. **OQ-3 支付服务商与币种**：Stripe/PayPal（海外）或微信/支付宝/其他（中国大陆）？影响：FR-54/55、发票与税务、上线地区。
4. **OQ-4 法规辖区**：主要运营地区（中国大陆/港澳台/欧盟/美国…）？影响：实名认证、数据驻留、未成年人保护、内容审核义务、隐私政策。
5. **OQ-5 苹果/谷歌开发者账号主体**：个人/企业？影响：APNs/FCM 配置、签名、商店审核与 VoIP/CallKit 权限。
6. **OQ-6 音视频与转码**：SFU/媒体服务选型与编解码许可（自建 vs 托管）？影响：FR-24、FR-35…37 成本与许可。
7. **OQ-7 RPO/RTO 目标与部署规模**：首发预期 DAU/连接数？影响：架构、压测目标、灾备预算。
8. **OQ-8 短信通道**：服务商与地区覆盖？影响：FR-1、成本与风控。
9. **OQ-9 对象存储**：S3 兼容服务商/自建？影响：FR-22/23、成本与可用性。
10. **OQ-10 Manager/Web 授权**：用户已接受风险；是否仍联系上游作者以降低风险？
11. **OQ-11 客服深度**：首发包含哪些客服能力（工单/知识库/质检）？影响：FR-38…40 排期。
12. **OQ-12 开放平台实名与结算**：个人开发者是否需实名；是否开启开发者结算？影响：法务与支付。
